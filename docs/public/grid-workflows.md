# Отбор и редактирование данных в GridControl

Пример открывается командой `cargo run --release -p xaml-form -- --grid-workspace`. Вкладки под таблицей содержат форму строки, построитель условий, дерево разделов и связи заказа. Доступны позиции, платежи и примечания к отдельной позиции.

## Отбор и поиск

Щелчок по названию колонки сортирует записи по возрастанию, повторный щелчок — по убыванию. Шеврон справа показывает текущее направление. В демонстрационной форме начальная сортировка задана по коду. В сгруппированной таблице записи сортируются внутри каждой группы. Щелчок по полю на панели группировки меняет порядок групп этого уровня. При сортировке групп по итогу щелчок меняет направление сравнения итогов. Shift+щелчок добавляет колонку или меняет её направление, сохраняя её место в порядке сортировки. Число рядом со стрелкой обозначает приоритет. С клавиатуры Alt+↑ сортирует по текущей колонке, Alt+Shift+↑ добавляет её в сортировку. В Rust `set_grid_sort_priority` задаёт порядок конкретных типизированных значений. При равенстве всех полей сортировки порядок определяет знаковый ключ записи.

`ShowAutoFilterRow="True"` включает строку отбора. Щелчок открывает ввод, Enter применяет условие, Escape отменяет ввод. Для текста по умолчанию ищется подстрока без учёта регистра. Операторы `=`, `!=`, `<`, `<=`, `>`, `>=` сравнивают типизированные значения. Например, `>=10` отбирает количество, а `01.11.2026..30.11.2026` включает обе границы диапазона дат. `NULL` отбирает отсутствующее значение. Очистка ввода снимает отбор одной колонки.

Воронка в заголовке или Alt+↓ в текущей колонке открывает фильтр рядом с заголовком. На вкладке **Значения** показаны подписи и количество записей с учётом условий других колонок. Поиск сужает список по подписи. Флажок «Все найденные» меняет только показанные значения. Пустая строка и NULL различаются. На вкладке **Правила** можно задать типизированное условие для этой колонки. Обе вкладки применяются одной кнопкой «Применить» или клавишей Enter. «Сбросить» и Delete снимают оба условия текущей колонки. Escape отменяет черновик. Активный фильтр отмечен акцентным цветом воронки.

Tab переключает вкладки, стрелки и Page Up / Page Down перемещают курсор списка, пробел меняет отметку. Ctrl+A в поле ввода позволяет заменить текст целиком. Правый щелчок открывает настроенное меню колонки или, при отсутствии меню, список значений. Для программного управления списком служат `grid_facet_values` и `set_grid_facet`. Воронка доступна для локальных табличных источников с полным набором значений.

Построитель и таблица могут использовать один путь модели. `Criteria` хранит каноническое типизированное выражение с вложенными `all`, `any` и `not`. `IsCriteriaEnabled` временно отключает применение этого выражения, сохраняя его в модели. Условия отдельных колонок продолжают действовать. Некорректный ввод сохраняет последний принятый запрос.

```xml
<StackPanel>
  <FilterBuilder DataSource="Orders" Value="{Binding Rule}"/>
  <CheckBox Content="Применять условие" IsChecked="{Binding RuleEnabled}"/>
  <GridControl DataSource="Orders" Criteria="{Binding Rule}"
               IsCriteriaEnabled="{Binding RuleEnabled}"
               ShowAutoFilterRow="True" ShowRowSelector="True"/>
</StackPanel>
```

Ctrl+F открывает поиск, Enter выбирает совпадение, F3 и Shift+F3 переходят вперёд и назад с циклическим обходом. Совпадающие ячейки подчёркнуты. Набор в самой таблице ищет в текущей колонке. Пауза более секунды начинает новую строку поиска. Открытый редактор ячейки получает обычный текстовый ввод.

## Источник, черновик и проверка строки

`replace_grid_source` заменяет источник у существующего виджета. Автоматические колонки следуют схеме, текущая запись сохраняется по ключу, если он существует. Явные колонки, привязки связей и зарегистрированные редакторы требуют совместимой схемы. Перед заменой источника завершите клеточный и строковый редакторы.

1. Для новой записи передайте приложенческие значения по умолчанию и постоянный ключ в `begin_grid_insert`. Для существующей используйте `begin_grid_row_edit`.
2. Меняйте значения через `set_grid_draft_cell`. Источник обновляется при `commit_grid_record` одним пакетом. `cancel_grid_record` отбрасывает изменения, `delete_grid_record` удаляет запись с проверкой исходных значений.
3. `set_grid_row_validator` получает схему и полную строку. Возвращённый `GridRowIssue` содержит имя поля и сообщение. Для исходной строки проверяется оптимистическое ожидание внутри транзакции адаптера. Ошибка сохраняет черновик.
4. `SelectedValue` сообщает текущий ключ через привязку. `take_grid_record_events` выдаёт события текущей строки, открытия, отмены, записи и удаления в порядке возникновения. Буфер хранит последние 256 событий.

Для пакетной операции источник должен поддерживать соответствующую возможность CRUD и атомарную запись. Действуют ограничения источника, схемы и самого Grid. Добавление может инициализировать служебное поле, дальнейшее изменение соблюдает его режим чтения.

## Выделение и обмен

`ShowRowSelector="True"` добавляет колонку выбора. Щелчок по её заголовку или Ctrl+A выбирает видимые строки. Логическое выделение использует ключи. Видимость и расположение колонок определяют порядок полей. Протягивание по ячейкам создаёт прямоугольник, Ctrl с протягиванием добавляет отдельный диапазон. Shift со стрелками расширяет выбор от исходной ячейки.

Ctrl+C копирует TSV и HTML-таблицу, Ctrl+Alt+C включает заголовки. Для раздельных диапазонов обе формы используют объединение выбранных строк и колонок, оставляя пропуски пустыми. В программном API доступны `copy_grid_selection` и `paste_grid_tsv`. Ctrl+V вставляет текст от текущей ячейки. Поля разбираются по схеме, кавычки сохраняют табуляцию и переносы, весь прямоугольник проверяется перед записью. При наличии первой строки заголовков передайте `headers = true` в `paste_grid_tsv`. Для обмена через текст NULL отображается пустым полем, при вставке в строковую колонку это пустая строка. Предел обмена составляет 4 МиБ, предел пакета адаптера — 1024 операции.

`configure_grid_row_drop` разрешает внутреннее перетаскивание с Alt. В одном источнике порядок хранится в указанной целочисленной колонке. Сортировка по этой колонке показывает результат перестановки. Между разными источниками с одинаковой схемой данные копируются в одной транзакции с сохранением ключей. Конфликт ключей отменяет пакет.

Однооконный хост Windows поддерживает OLE для Unicode-текста. В примере Ctrl+Alt с перетаскиванием начинает внешний перенос. Принимающая ячейка разбирает TSV и подтверждает результат после записи. Перемещение из Grid требует явного `allow_grid_external_move`, всех полей хранения в исходном порядке и разрешения источника на удаление. После подтверждения получателя источник проверяет полные исходные строки перед удалением. Отмена сохраняет записи. Собственный хост может подключить текстовую цель через методы `DesktopApp`.

## Представления и связи

Карточки используют видимые поля и их порядок, автоматически меняя число карточек по ширине окна. Для каждого ряда карточек общие прокрутка, геометрия попадания и координаты редактора. Переключение между `Table` и `Cards` сохраняет ключ текущей записи.

`ParentField="ParentId"` строит дерево из записей с целочисленным ключом. Поле родителя допускает NULL для корней. Неизвестные родители и циклы отклоняются. Фильтр оставляет путь к подходящей записи, сортировка упорядочивает соседей. `set_grid_child_loader` задаёт загрузчик непосредственных детей по ключу. Раскрытие запрашивает ветку один раз и проверяет родителя у каждой полученной записи. Пустая ветка запоминается, ошибку можно повторить. Для этого режима используется отдельная проекция без групп, итогов и встроенных строк подробностей.

```xml
<GridControl DataSource="Orders">
  <GridControl.Relations>
    <GridRelation Name="Items" DataSource="Lines" MasterField="Id" ForeignField="OrderId">
      <GridColumn FieldName="Product" Header="Товар"/>
      <GridColumn FieldName="Quantity" Header="Количество"/>
    </GridRelation>
  </GridControl.Relations>
</GridControl>
```

`open_grid_relation(master, key, "Items", host, style)` монтирует полноценный Grid в выделенном контейнере и возвращает его WidgetId. Поля связи должны иметь одинаковый тип. Внешний ключ доступен для чтения, отбор, выбранная ячейка и черновик принадлежат экземпляру дочерней таблицы. Изменения записываются в источник позиций. На дочернем Grid можно зарегистрировать следующую связь через `register_grid_relation`. Переключение связи в том же контейнере сохраняет ранее открытый экземпляр. `close_grid_relation` освобождает его после завершения редактирования. Один master удерживает до 128 открытых экземпляров.
