# JSON и CSV

Feature `file-adapters` в `rust-desktop-ui-data` включает чистые кодеки и
`FileDataAdapter`. Адаптер реализует общий `DataAdapter`: загрузка, обновление
одной ячейки и атомарный пакет Insert/Update/Delete. Доступ к файлам выполняется
только при явных вызовах. `DataSource` хранит последний принятый снимок и не
читает файл при обращении к ячейкам.

```rust
use rust_desktop_ui_data::{
    DataFileOptions, DataSource, FieldSchema, FieldType, FileAccess,
    FileDataAdapter, FileTableMapping, TableSchema,
};

let schema = TableSchema::new(vec![
    FieldSchema::new("caption", FieldType::Text),
    FieldSchema::new("amount", FieldType::Decimal),
])?;
let mapping = FileTableMapping::new(schema, "key")?;
let adapter = FileDataAdapter::open(
    "documents.json", mapping, DataFileOptions::default(), FileAccess::ReadWrite,
)?;
let source = DataSource::new(adapter)?;
# Ok::<(), rust_desktop_ui_data::DataError>(())
```

`FileTableMapping::with_columns` задаёт внешние имена полей отдельно от имён
схемы. Имена регистрозависимы, уникальны, содержат 1–256 байт и не содержат
управляющих символов. Колонка ключа всегда отдельная. Она хранит стабильный
`i64`, а не позицию строки. Типы не определяются по первым строкам; изменение
порядка строк не меняет ключи.

`decode_data_file` и `encode_data_file` работают с байтами без файлового I/O.
Ошибки не возвращают частичный результат. Неизвестные, отсутствующие или
повторные колонки, повторные ключи, неверные типы и запрещённый `null`
отклоняются. Для пустой таблицы схема всё равно проверяется.

## JSON

Файл содержит массив объектов. Порядок полей внутри объекта произволен, но
каждое имя mapping присутствует ровно один раз. Повторные JSON keys проверяются
во время разбора до построения словаря.

| Тип | Представление |
| --- | --- |
| Ключ и Integer | Каноническая десятичная строка; импорт также принимает точный JSON integer token в диапазоне i64 |
| Decimal | Каноническая строка без экспоненты, до 28 дробных цифр |
| Bool | `true` / `false` |
| Real | Конечное JSON number, с сохранением f64 при повторном чтении |
| Text | JSON string, включая пустую строку |
| Date | Строка `YYYY-MM-DD` |
| Time | Каноническая строка `TimeValue`, с сохранением секунд и наносекунд |
| Binary | Строка `0x` и пары строчных hex-цифр |
| Null | `null`, только для nullable поля |

```json
[
  {"key":"9223372036854775807","caption":"Документ","amount":"12345.67"}
]
```

Integer/Decimal/ключи не преобразуются через `f64`. Для Integer строка `01`,
`+1` или `-0` неканонична. Real принимает integer token только при его точной
представимости в `f64`; например, значение выше точности мантиссы не округляется
молча. Decimal не принимает JSON number: необходима точная строка. Объекты и
массивы внутри ячеек не поддерживаются.

## CSV

Выберите `DataFileFormat::Csv(CsvOptions { delimiter: b';' })`. Разделитель —
печатный ASCII, кроме кавычки, обратной косой черты и `N` из null marker.
Заголовок обязателен;
порядок его колонок может отличаться от mapping. Пустые и лишние записи
не пропускаются автоматически.

Кавычки разрешены в начале поля, внутренние кавычки удваиваются. Поле в кавычках
может содержать разделитель, CR и LF. После закрывающей кавычки допустимы только
разделитель, конец записи или файла. Экспорт использует CRLF, импорт принимает
CRLF, LF и CR. Пробелы сохраняются, автоматического trimming нет.

| Ячейка CSV | Значение nullable Text |
| --- | --- |
| `\N` без кавычек | Null |
| `"\N"` | Буквальный текст `\N` |
| Пустое поле / `""` | Пустая строка |

Остальные типы используют канонические строки из таблицы выше, Bool —
`true`/`false`. Пустая числовая ячейка не становится Null: нужен `\N`.
Схема и выбранный null sentinel являются частью контракта обмена; обычная
таблица CSV без этой схемы сама по себе не хранит типы.

## Кодировки и пределы

`FileEncoding` поддерживает UTF-8, UTF-8 с BOM, UTF-16LE и UTF-16BE.
При чтении UTF-8 BOM необязателен в обоих UTF-8 режимах; при записи его добавляет
только `Utf8Bom`. UTF-16 всегда записывается с BOM, чтение допускает его отсутствие
при явно выбранном порядке байтов. Несовпадающий BOM, неверный UTF-8, непарные
суррогаты и нечётное число UTF-16 байт отклоняются. Автоопределения legacy
кодировок и замены повреждённых символов нет.

`max_file_bytes` ограничивает исходные/выходные байты и промежуточный UTF-8 текст;
максимум 128 MiB, может быть уменьшен. `DataLimits` отдельно ограничивает строки,
поля, payload ячейки и итоговую таблицу (по умолчанию 100 000 строк, 128 полей,
1 MiB Text/Binary ячейка, 64 MiB таблица). Экранирование, BOM и размер UTF-16
учитываются в выходном пределе. Память для входного файла, декодированного текста,
кандидата таблицы и принятого снимка может существовать одновременно; табличный
лимит не является общей квотой heap.

Диагностика содержит номер записи/колонки или имя поля, без содержимого ячейки.
В quoted multiline CSV номер записи означает логическую запись, а не строку
текстового редактора. Ошибки формата не скрываются преобразованием типов.

## Жизненный цикл файлов

`open` читает существующий обычный файл; символьная ссылка не принимается.
`create` создаёт только отсутствующий файл и возвращает ReadWrite adapter;
существующая цель — Conflict. Каталог должен существовать. `FileAccess::ReadOnly`
не разрешает запись. `accepted_table()` возвращает последний успешный снимок
без I/O. `load` / `DataSource::refresh` явно перечитывают данные. Нет фонового
watcher или автоматического сохранения.

Запись проверяет весь пакет expectations/readonly/типов/лимитов на отдельной
таблице, полностью кодирует результат и только затем заменяет файл. Для writers
этой библиотеки используется `try_lock` на соседнем `<имя>.ui-data.lock`.
Lock-файл сохраняется между вызовами; его существование не означает занятость.
Сравниваются точные байты последнего принятого файла, поэтому даже внешняя
переформатировка требует явного refresh.

Новый файл записывается в уникальный временный файл того же каталога,
`sync_all` завершается до повторной проверки исходных байтов и rename.
Ошибка до rename сохраняет исходный файл и accepted snapshot; временный файл
удаляется при выходе. После успешного rename нет fallible callbacks или
повторного разбора, способного превратить успешную внешнюю запись в ошибку.
`DataSource` увеличивает revision после успешной публикации, не после неудачного
refresh, validation или conflict.

Сравнение и rename не составляют межпроцессный CAS для произвольного стороннего
writer: приложение, которое игнорирует sidecar lock, может записать файл между
последним сравнением и заменой. Поддерживается атомарная замена средствами ОС
на локальной файловой системе; специфические гарантии сетевой FS и сохранность
после сбоя питания, метаданные/ACL старого файла и directory fsync не обещаются.
Адаптер не является механизмом защиты от враждебной подмены путей.

## Пример и проверки

Самостоятельный пример работает с фиксированной типизированной схемой:

```text
cargo run -p rust-desktop-ui-data --features file-adapters --example file_roundtrip -- create-json documents.json
cargo run -p rust-desktop-ui-data --features file-adapters --example file_roundtrip -- inspect-json documents.json
```

Аналогичные команды `create-csv` / `inspect-csv` используют CSV. Создание не
перезаписывает существующий файл. Тесты покрывают типы и точные ключи во всех
кодировках, nullable/empty/multiline CSV, JSON duplicates, лимиты, конфликты,
целостность accepted snapshot и отказ Windows rename при запрете удаления цели.
