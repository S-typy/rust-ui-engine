# Панели, вкладки и отдельные окна

Docking разделяет расположение панелей и их содержимое. `DockLayout` хранит
дерево вкладок и разделителей; `DockView` рисует заголовки, кнопки, разделители
и предварительную область переноса. Приложение владеет документами панелей,
составляет их сцены и создаёт отдельные нативные окна через `run_multi`.

В [DockWindow.xaml](../../examples/xaml-form/DockWindow.xaml) представлены
обозреватель, документ, заметки, свойства и вывод. Запуск:

```sh
cargo run --release --locked -p xaml-form -- --docking
cargo run --release --locked -p xaml-form -- --docking --float-pane Properties
cargo run --release --locked -p xaml-form -- --docking --dark
```

Флаг `--float-pane` принимает `Id` панели и открывает её в отдельном окне при
старте. Обычный запуск без `--docking` сохраняет прежнюю форму с Ribbon.

## Модель расположения

Модель находится в `rust-desktop-ui-controls` и не зависит от winit, GPU или
оконных дескрипторов. `DockPaneId` обозначает постоянную панель, `DockGroupId`
и `DockSplitId` — узлы расположения, `DockWindowId::MAIN` — главное окно.
`DockNode::Tabs` хранит список панелей и активную вкладку. `DockNode::Split`
делит область на два дочерних узла: `Horizontal` означает слева/справа,
`Vertical` — сверху/снизу. Доля `ratio` относится к первому дочернему узлу.

| API | Назначение |
|---|---|
| `DockLayout::new`, `from_snapshot` | Проверить каталог панелей и начальное расположение |
| `activate` | Выбрать вкладку в её группе |
| `move_pane` | Переставить вкладку, создать соседнюю группу или закрепить у края окна |
| `float_pane` | Перенести панель в новое отдельное окно |
| `redock_window`, `redock_window_at` | Вернуть панели отдельного окна в главное расположение |
| `close`, `restore` | Скрыть панель и вернуть её в явно выбранное место |
| `resize`, `update_floating_bounds` | Изменить разделение или сохранённую геометрию окна |
| `arrange` | Рассчитать группы, полосы вкладок, области содержимого и разделители |
| `snapshot`, `restore_snapshot` | Получить и восстановить типизированное расположение |

Изменение проверяется до принятия: ошибка оставляет прежнее расположение.
Каждая панель принадлежит ровно одной открытой группе либо списку закрытых.
Закрытие последней вкладки удаляет пустую группу и ненужный разделитель.
`CanClose=False` запрещает закрытие панели, сохраняя возможность её перемещения.
Размеры содержимого задаются отдельно от высоты полосы вкладок; фактические
доли разделения учитывают минимальные размеры и доступную площадь окна.

Пределы: 64 панели, 16 отдельных окон плюс главное, 32 уровня дерева.
`DockSnapshot` версии 1 содержит дерево главного окна, деревья и геометрию
отдельных окон и список закрытых панелей. Он не содержит тексты документов,
WidgetId, HWND или GPU-объекты. Файловый формат, кодирование и автоматическая
запись снимков пока не предоставляются.

## Представление и взаимодействие

`DockView::update` получает модель и область в логических координатах окна.
После него приложение выполняет обычный `Controls::update`. Содержимое активных
панелей добавляется через `Scene::append_view`: смещение и прямоугольное
отсечение сохраняют исходные размеры текстовых блоков и скруглений. Сцена
предварительной области переноса добавляется последней через `overlay_scene`.
Порядок композиции: `Controls::base_scene`, содержимое панелей,
`Controls::overlay_scene`, затем `DockView::overlay_scene`. Так меню, KeyTips
и ToolTip главного окна остаются поверх панелей. Обычный `Controls::scene`
по-прежнему возвращает полную сцену для представления без вложенных арен.

`handle_input` вызывается перед `Controls::dispatch`; поглощённое событие
не передаётся повторно. Метод возвращает `DockRequest`, которые приложение
применяет к общей модели. Обычные кнопки заголовка используют controls и
`process_activated`. Перетаскивание вкладки предлагает место во вкладках,
соседнюю группу или край рабочей области. Разделитель изменяет долю областей.
Escape отменяет текущий перенос или возвращает исходное положение разделителя.
Вкладки поддерживают стрелки, Home/End и активацию Enter/Space; разделитель —
стрелки соответствующей оси. Это контракты обработки событий, а не утверждение
о выполненной проверке нативного ввода на каждой платформе.

В демонстрации каждый `DockPaneId` связан с одним экземпляром `Form` на всё
время работы. Перестройка дерева, скрытие, открытие отдельного окна и возврат
меняют размещение этого экземпляра. Текст, выделение, история редактора,
принятое значение и настройки не восстанавливаются из заново созданного XAML.
Обычные правила validation/commit/cancel, включая `CommitOnLostFocus`, сохраняются.

Закрытие панели скрывает её, оставляя содержимое для восстановления. Закрытие
отдельного нативного окна возвращает его панели в главное окно. Закрытие
главного окна завершает приложение и закрывает принадлежащие ему окна.
Кнопки заголовка и команды Ribbon предоставляют действия открытия отдельного
окна, закрепления, восстановления панелей и сброса расположения.

## Compiled XAML

```xml
<Window xmlns="urn:rust-ui-engine:ui"
        Title="Workspace" Width="1000" Height="700" Padding="0">
    <DockWorkspace>
        <DockSplit Orientation="Horizontal" Ratio="0.7">
            <DockGroup SelectedPane="Document">
                <DockPane Id="Document" Header="Документ" CanClose="False"
                          MinWidth="280" MinHeight="180">
                    <StackPanel Padding="16">
                        <TextBox Text="Содержимое документа" />
                    </StackPanel>
                </DockPane>
            </DockGroup>
            <DockGroup>
                <DockPane Id="Properties" Header="Свойства"
                          MinWidth="180" MinHeight="120">
                    <StackPanel Padding="16">
                        <TextBox Text="Название" />
                    </StackPanel>
                </DockPane>
            </DockGroup>
        </DockSplit>
    </DockWorkspace>
</Window>
```

`DockWorkspace` содержит один `DockSplit` либо `DockGroup`; `DockSplit` — ровно
два таких узла. `DockGroup` содержит панели, `SelectedPane` выбирает одну из них,
по умолчанию выбирается первая. `DockPane` содержит один обычный элемент дерева
формы. `Id` уникален и соответствует `[A-Za-z_][A-Za-z0-9_]*`, не более 128 байт.
`Ratio` — конечное число от 0.1 до 0.9. Заголовок непустой, не более 4096 байт;
минимальные размеры положительные и не превышают 16384 логических пикселей.

Разрешён один workspace на Window; Ribbon и вложенный workspace внутри панели
не поддерживаются. Пример соединяет верхний Ribbon и workspace вертикальным
контейнером. Для этой оболочки требуется `Window Padding="0"`. Общие свойства
корня, Ribbon и DockWorkspace ограничены `x:Name`: размеры остаются Auto,
Margin — нулевым, IsEnabled — стандартным; shell overrides AutomationName и
ToolTip не поддерживаются. Корневая StackPanel прозрачна, имеет нулевой Padding
и допускает Spacing от 0 до 256; этот интервал учитывается между Ribbon и
workspace. Обычные свойства элементов внутри DockPane сохраняются.
`x:Name` остаются уникальными в полном исходном Window, включая
неактивные панели. Общие ограничения числа и глубины элементов compiled XAML
действуют также на содержимое панелей. XML и вручную построенные определения
проверяются до монтажа. Полный профиль — [XAML](xaml.md).

## Несколько нативных окон

`rust-desktop-ui-platform-winit::run_multi` принимает `DesktopApplication`.
Приложение возвращает желаемый набор `WindowSpec` и предоставляет `DesktopApp`
для каждого `WindowKey`; ключ независим от winit и ОС. Прежний `run` остаётся
совместимым с приложениями, использующими одно окно.

| Контракт | Поведение |
|---|---|
| `windows(&mut self)` | Полный желаемый набор окон; пустой набор завершает цикл |
| `window`, `window_mut` | Доступ к постоянному представлению по ключу |
| `close_requested` | Решение приложения: оставить окно либо убрать его из желаемого набора |
| `window_closed` | Представление можно удалить после очистки ввода и уничтожения нативного окна |
| `WindowSpec` | Ключ, RunOptions, начальная позиция, owner и разрешение активации |
| `window_geometry_changed` | Фактическая позиция внешней рамки, клиентский размер и масштаб |

При удалении окна приложение сохраняет его представление до `window_closed`.
Host сначала передаёт потерю фокуса, если окно было сфокусировано, затем отмену
IME и уход указателя. Окна с владельцем закрываются до владельца. Позиция и
размер из спецификации используются при создании: последующие обновления
модели не отменяют перемещения и изменения размера, сделанные пользователем.
Изменение owner существующего окна требует нового ключа. Неверные ключи,
геометрия, отсутствующий owner и циклы ownership отклоняются до перехода.

Каждое окно имеет собственные renderer/surface, DPI, IME session, modifiers,
указатель, таймеры и AccessKit adapter. Clipboard общий, но результат Paste
возвращается представлению, которое запросило чтение. Запрос redraw обновляет
все окна, чтобы изменения общего состояния были видимы в каждом представлении.
Ошибка приложения или renderer завершает host с ошибкой.

На Windows `owner` задаёт настоящее отношение владельца нативного окна.
Отдельные панели используют обычную рамку; главное окно может сохранять
объединённую шапку Ribbon. На других платформах окна сохраняют обычное оформление;
эквивалентное нативное ownership и runtime ещё требуют отдельной реализации
или проверки. В этом профиле renderer/device создаётся отдельно для каждого
окна; совместное использование GPU-ресурсов между окнами пока не введено.

## Accessibility и пределы проверки

Демонстрация объединяет полные деревья активных панелей в дерево окна, сохраняя
заранее выделенные стабильные диапазоны NodeId. Физические bounds смещаются
и отсекаются по области панели. Корень панели становится контейнером; скрытые
панели не входят в дерево. Actions направляются владельцу узла, focus берётся
только из выбранной панели. Эти данные не заменяют проверку экранным диктором.

Нативный ввод, межмониторный DPI, IME при переносе редактора и screen reader
для docking пока не проверены. Windows GPU снимки, resize и lifecycle без ввода
проверяются отдельно. Linux/macOS native runtime также остаётся отдельной
проверкой. Direct drag между двумя уже открытыми нативными окнами, auto-hide,
MDI, панели поверх произвольных окон, произвольные templates и готовый файловый
кодек расположения не входят в текущий профиль. Перенос между окнами доступен
через отдельное окно и явное закрепление в основном workspace.

Архитектурная граница закреплена в [ADR-007](adr/ADR-007-docking-windows.md).
