# Представления GridControl

`GridControl` использует принятый снимок `DataSource`, общий `QueryEngine` и
виртуальную геометрию `TreeGrid`. Сортировка/фильтр остаются у источника;
настройки представления принадлежат конкретному контролу. Рисование и методы
чтения не выполняют запросы SQLite. Обычная плоская таблица и текстовый редактор
остаются поведением по умолчанию.

## Группы и итоги

`GridPresentationSettings` задаётся через `set_grid_presentation`.
`group_fields` содержит до восьми уникальных полей. Это один составной ключ
группы, а не восемь вложенных уровней. До 4096 групп раскрываются первоначально;
последующее обновление сохраняет раскрытие по типизированному ключу группы.
Enter на заголовке группы переключает раскрытие, стрелки перемещают фокус.

До 16 `GridSummary` содержат `ui_data::Aggregate`: CountRows, CountValues, Sum,
Minimum, Maximum или Average с типизированным выражением. Общие итоги показаны
снизу, итоги группы — в её подписи. NULL, сравнение, decimal arithmetic и ошибки
переполнения определены [контрактом запросов](query.md). Ошибка вычисления
кандидата не устанавливает новые настройки и не меняет общий query источника.

Ключи записей сохраняют все биты `i64`. Служебные строки получают отдельные
ключи, не совпадающие ни с одной записью принятого снимка. Вставка записи,
занявшей бывший служебный ключ, переназначает служебную строку по её устойчивой
идентичности. Новая группа не забирает ключ существующей группы. Для определения
типа строки используется `grid_row_kind`, а не преобразование RowKey в i64.
`GridRowKind::Group.key` содержит непрозрачную типизированную идентичность;
это не строка для отображения или стабильный файловый формат.

## Колонки, полосы заголовков и карточки

`GridBand` объединяет непересекающиеся наборы полей. Соседние видимые колонки
имеют общий заголовок; скрытие, перестановка и закрепление могут разделить полосу
на несколько фрагментов. Геометрия фрагментов вычисляется из текущего кадра.

`grid_arrangement` возвращает порядок, видимость, ширину и закрепление всех
колонок. `arrange_grid_columns` принимает каждое поле ровно один раз и требует
хотя бы одну видимую колонку. Недопустимые размеры отклоняются атомарно.
Клавиши Left/Right следуют визуальному порядку закреплённых и обычных колонок,
не переключая выбор записи. Настройки не меняют схему источника.

`GridViewMode::Cards` показывает одну вертикальную карточку на логическую
строку, с полями сверху вниз. Это виртуальный одноколоночный список карточек,
не многоколоночная мозаика. Число полей определяет высоту карточки; горизонтальная
прокрутка отсутствует. Порядок/видимость полей сохраняются, bands скрыты.
Группы, подробности, итоги и редакторы используют те же идентичности.

## Подробности

`set_grid_detail` принимает `GridDetailSettings`: отдельный зарегистрированный
источник, master_field, foreign_field и колонки подробностей. Типы полей связи
должны совпадать. NULL не связывает строки. Несколько подробностей могут иметь
одно внешнее значение; если значение есть у нескольких master records,
подробности представлены отдельно для каждой такой записи.

Поддерживается один уровень read-only подробностей. Внутри раскрытой записи
показана строка заголовков подробностей, затем связанные записи. Их колонки
используют геометрию соответствующих по номеру master columns; колонок
подробностей должно быть от одной до числа master columns. Выбор подробности
не подменяет SelectedValue основного источника. Оба источника имеют независимые
версии; изменения принятого detail snapshot учитываются при следующем update.
Во время активного редактирования snapshot этой таблицы остаётся прежним.

## Шаблоны ячеек и редакторы

`GridCellTemplate` — ограниченная декорация существующего значения: prefix,
suffix (по 256 байт), собственный векторный icon и emphasis. Она не создаёт
retained widget на каждую ячейку и не меняет storage value. При изменении
представления проверяются окончательные строки после объединения компонентов,
включая Unicode grapheme boundaries. Новые offscreen values проверяются при
попадании в отображаемый кадр; ошибка текста возвращается как обычная ошибка,
а не заменяется фиктивной картинкой.

`set_grid_editor_factory(id, field, name, &DataFormFactories)` использует
существующие рецепты редакторов. Auto выбирает CheckBox для Bool, Numeric для
Integer/Decimal, Date/Time для соответствующих типов и Text для остальных.
В Rust реестр позволяет зарегистрировать собственное имя существующего
типизированного рецепта. Произвольные callbacks или отражение типов не вызываются
во время записи. XAML-пример использует стандартный реестр рецептов.

Активен один retained editor host. Numeric сохраняет точные значения, включая
целые выше 2^53; nullable Bool имеет третье состояние. Календарь и калькулятор
работают через обычную сессию редактора. После завершения host скрывается и
удаляется перед следующей типизированной сессией: это позволяет callback popup
закончить работу со своим владельцем. Черновик не переносится в другую запись.

`set_grid_edit_value` меняет только типизированный черновик. `commit_grid_edit`
проверяет схему, synchronous/async validator и исходное ожидаемое значение ячейки
перед записью. False означает invalid или pending; подробности доступны через
editor validation status и `grid_error`. Async completion не записывает значение
после cancel; конфликт оставляет введённый текст. Программное изменение настроек
типизированного редактора вне его рецепта отклоняет commit до изменения источника.
Cancel и повторное открытие восстанавливают рецепт.

Смена query, представления, шаблона, набора колонок или раскрытия при активном
черновике возвращает ошибку. Скрытая колонка не может открыть редактор; отказ
происходит до загрузки accepted text, создания host или смены выбора.
ReadOnly/недоступный владелец блокируют запись. Проверки внешнего RefCell borrow
возвращают ошибку, не паникуют и не начинают операцию ввода.

## Виртуализация и доступность

Всего допускается до миллиона строк представления, включая группы и подробности,
до 64 колонок, 16 bands и 4096 одновременно сохранённых раскрытий. Высота карточки
фиксирована для текущего набора полей. Сохраняются ключ и дробное смещение верхней
строки; исчезнувшая служебная строка использует общий fallback scroll anchor.
Тест со 100 000 записей проверяет ограниченное число строк/ячеек в кадре и отсутствие
роста retained tree при прокрутке группированных карточек.

AccessKit-проекция публикует визуальный порядок колонок, Row/Cell, раскрытие,
read-only подробности, итоги и bands. В карточках нет фиктивных заголовков таблицы.
Действия от устаревшего снимка игнорируются до обновления; служебная строка не
получает действие записи. `grid_snapshot_is_current` проверяет версии обоих
принятых источников без provider I/O. Ограничения системного GridPattern указаны
в [основном контракте](grid-control.md). Фактические проверки экранным диктором
и native input описываются отдельно от unit-проекции.


В текущем Windows provider нет native Grid/Table и GridItem/TableItem patterns.
Семантическая проекция уже содержит реальные количества строк/столбцов и индексы
видимых ячеек, но эти свойства не обеспечивают системную табличную навигацию.
Narrator может объявлять «столбцы 0 и строки 0»; чтение и переходы по ячейкам
через команды экранного диктора не поддерживаются. Это ограничение общей
табличной доступности, а не нулевой размер модели.

Сохраняются обычная клавиатурная навигация приложения, выбор строк и доступные
значения материализованных ячеек. F2 в доступной редактируемой ячейке открывает
настоящий типизированный редактор с собственным writable Value/RangeValue
pattern; read-only ячейки и подробности запись не получают. Эти возможности
не заменяют отсутствующие native table patterns и полноценное чтение таблицы.

Compiled XAML metadata: [разметка представлений](grid-presentation-xaml.md).

## Пример

```text
cargo run --release --locked -p xaml-form -- --grid-workspace
```

Пример содержит10 000 записей, независимый источник подробностей, группировку,
итоги и bands. Кнопки переключают таблицу/карточки, порядок и видимость колонок,
закрепление и редактор выбранного поля. «Конфликт записи» моделирует внешнее
изменение принятого значения. Источники живут в памяти; пример не записывает
пользовательские файлы и не подключается к базе автоматически.
