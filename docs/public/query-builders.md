# Построители фильтров и выражений

`FilterBuilder` редактирует типизированный `Criteria`, а `ExpressionBuilder` —
`QueryExpression`. Оба используют схему `TableSchema`, общую проверку типов
`QueryEngine` и один текстовый codec. Компоненты не выполняют запрос и не меняют
строки источника: приложение получает `QueryBuilderApplied` после явного Apply.

## Принятое значение и черновик

`query_builder_value` возвращает принятое значение; `query_builder_draft` —
последнее корректное дерево черновика, `query_builder_text` — текущий текст,
который может быть некорректным. Ошибка доступна через `query_builder_error` и
подпись состояния. Apply проверяет синтаксис, типы, валидаторы источника и
приложения до публикации значения и события. Повторный Apply неизменённого
значения не создаёт дополнительного события. Cancel восстанавливает принятое
значение без записи в источник. Ctrl+Enter соответствует Apply, Escape сначала
отменяет IME-композицию, затем черновик.

Внешняя замена `set_query_builder_value(..., false)` отклоняется при грязном
черновике или активной композиции. Параметр `discard_draft=true` явно разрешает
их отбросить после успешной проверки нового значения. Изменение режима, текста,
визуального узла и Apply также отклоняются при композиции в любой части редактора.
Состояние редактора и WidgetId сохраняются при изменении режима, темы и размера.

## Визуальный профиль

Дерево фильтра поддерживает группы И/ИЛИ/НЕ, константы, сравнение поля с
типизированным литералом, проверку NULL и текстовый поиск. Узел выбирается в
дереве; поле, оператор и значение задаются отдельными редакторами. Кнопка замены
создаёт узел, кнопки групп оборачивают выбранный узел, удаление удаляет узел из
группы. Тип значения определяется схемой, включая точные i64 и Decimal.

Визуальный профиль выражения включает поле, литерал, арифметику, coalesce,
lower и length над простыми операндами. Более сложное дерево сохраняется в
текстовом режиме. Переход такого дерева в визуальный режим возвращает
диагностику и сохраняет принятое значение. Текстовый режим покрывает все узлы
общего AST. Список дополнений содержит поля и доступные функции; вставка
использует положение каретки.

## Канонический текст

Синтаксис состоит из имён функций и типизированных литералов:

```text
all(ge(field("Count"),integer("5")),contains(field("Name"),text("проект")))
add(field("Amount"),decimal("0.01"))
```

Литералы: `null()`, `bool("true")`, `integer("-5")`, `real("0.5")`,
`decimal("12.50")`, `text("строка")`, `date("2026-10-17")`,
`time("12:30:45")`, `binary("00ff")`. Числа внутри кавычек сохраняют
тип и точность; Real допускает только конечные f64. Дата и время используют
форматы общих типов данных; дробные секунды допустимы.

Функции выражения: `field`, `add`, `sub`, `mul`, `div`, `lower`, `length`,
`coalesce`. Функции фильтра: `true`, `false`, `all`, `any`, `not`, `is_null`,
`eq`, `ne`, `lt`, `le`, `gt`, `ge`, `contains`, `starts_with`, `ends_with`.
Префикс `i` у трёх текстовых сравнений выбирает UnicodeLowercase.
Строки поддерживают экранирование кавычки, обратной косой черты, `\n`, `\r`,
`\t` и `\u{...}`. SQL не интерпретируется.

`parse_criteria_text` и `parse_expression_text` проверяют результат через
`QueryEngine`; `format_criteria_text` и `format_expression_text` возвращают
канонический текст. Текст ограничен 16 KiB UTF-8, дерево — 128 узлами и
16 уровнями. Ограничения применяются до рекурсивного разбора и накопления
вывода. Редактор допускает 1–128 полей, не более 16 построителей на Controls,
до 128 невычитанных Apply-событий и до 64 предложений дополнения.

## XAML и bindings

```xml
<FilterBuilder DataSource="Orders" Value="{Binding Filter}" />
<ExpressionBuilder DataSource="Orders" Mode="Text"
                   Value="{Binding Formula}" IsReadOnly="{Binding Locked}" />
```

Источник регистрируется приложением до монтажа формы. Из него читается схема;
построитель не подписывается на изменения строк и не выполняет запросы.
`Value` — строка канонического принятого запроса, по умолчанию
TwoWay/PropertyChanged; это означает публикацию после Apply, а не после
каждого символа. Ошибка внешнего binding сохраняет предыдущее значение
редактора. Валидатор источника остаётся действующим при замене валидатора
приложения. `IsReadOnly` блокирует редактирование и Apply, сохраняя просмотр.

Пример `xaml-form --query-builder` показывает оба построителя и явное
выполнение принятого запроса приложением над неизменяемой коллекцией.

## Проверки и ограничения

Unit-регрессии покрывают round-trip типов и Unicode, ранние лимиты, ошибки
схемы, визуальное/текстовое соответствие, Apply/Cancel и конфликты черновика,
валидацию binding, retained IDs, IME-composition guards и геометрию кнопок.
Проверка нативной IME и экранного диктора учитывается отдельно от этих тестов.
Полноценный редактор исходного кода, произвольная грамматика SQL и исполнение
выражений вне общего QueryEngine не предоставляются.
