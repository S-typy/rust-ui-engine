# Сводные таблицы

`PivotSnapshot` строит неизменяемую сводную таблицу из принятого `DataTable`. `PivotView` размещает её в постоянном `GridControl`: используются существующие виртуализация, клавиатурная навигация, отрисовка и семантическая проекция таблицы с ограничениями Windows, описанными ниже.

## Поля, значения и происхождение

`PivotDefinition` задаёт до двух `row_fields`, до двух `column_fields`, до восьми `PivotMeasure` и необязательный типизированный `Criteria` filter. Поля осей уникальны и не повторяются между осями. Каждая мера использует существующий `Aggregate` и правила `QueryEngine`; промежуточные и общие итоги вычисляются по исходным записям. Среднее итогов не заменяет среднее исходных значений. NULL, пустая строка, точные целые и Decimal сохраняют свои типы. Пустые пересечения используют обычную семантику агрегатов: Count=0, остальные агрегаты=NULL.

`PivotPathId` представляет ось, последовательность полей и типизированных значений. Он не совпадает с ключом исходной строки. Grid получает отдельные идентичности проекции; исходный диапазон ключей i64 остаётся доступен целиком. `PivotSourceId` создаётся для одного источника и клонируется между его версиями. При замене источника приложение создаёт новую идентичность.

`drill_down` принимает ожидаемую идентичность/версию источника и возвращает исходные ключи вместе с этой версией. Перед показом записей приложение снова проверяет версию. Пример показывает read-only проекцию исходных записей, а не редактирует агрегированные ячейки.

## Постоянное представление

```rust,ignore
let mut view = PivotView::mount(&mut ui, parent, source, definition, style)?;
// Перед передачей событий обычным Controls:
let consumed = view.before_input(&mut ui, &input)?;
view.update(&mut ui)?;
// При потере native capture:
view.cancel_pointer(&mut ui)?;
// Перед удалением представления или его владельца:
view.dispose(&mut ui)?;
```

`dispose` обязателен перед удалением представления/владельца: он освобождает capture, снимает зарегистрированные команды и удаляет собственное дерево. Обычный Rust `Drop` не имеет доступа к `Controls`.

`PivotView` сохраняет Grid и его внутренний редактор при обновлении конфигурации. Сохранившиеся пути удерживают выбор и раскрытие. При сворачивании выбранного дочернего пути выбирается ближайший видимый предок; если он исчез, используется первая строка. Grid восстанавливает привязку прокрутки к сохранившемуся ключу. Обновление исходной коллекции сначала строит и проверяет полный кандидат; ошибки оставляют последнее принятое представление.

Поля перетаскиваются между областями строк/столбцов. Ctrl+Left/Right меняет порядок, Ctrl+Up/Down переносит поле на соответствующую ось. Escape, потеря capture/фокуса, отключение владельца и новая версия источника отменяют незавершённый жест. Кнопки раскрывают/сворачивают путь выбранной строки или столбца и запрашивают исходные записи. Команда drill-down создаёт одно событие; выбор ячейки сам по себе его не создаёт.

`set_definition` меняет порядок осей, меры и filter в пределах смонтированного каталога полей. Для другого каталога создаётся новый `PivotView`. Синхронизация адаптера и I/O остаются у приложения; представление читает принятую таблицу и её revision.

## Доступность в Windows

Проекция передаёт реальные семантические row/column counts и индексы видимых
ячеек, native DataGrid role, выбор строк и read-only значения. Текущий Windows
provider не предоставляет Grid/Table и GridItem/TableItem patterns. Поэтому
Narrator может сообщать «столбцы 0 и строки 0» для сводной и исходной таблиц;
чтение агрегатов и навигация по ячейкам командами экранного диктора не
поддерживаются. Наличие числовых значений в UIA не означает, что они будут
прочитаны при табличной навигации.

Обычные клавиши приложения, выбор, раскрытие и перемещение полей продолжают
работать; подписи полей и инструкции доступны как отдельные элементы.
Агрегаты и drill-down пример остаются read-only. F2-редактор общего Grid
предназначен только для отдельно разрешённых редактируемых ячеек и не
устраняет это ограничение Pivot. Полноценная native табличная доступность
остаётся незавершённой.

## Ограничения и пример

Ограничения модели: 100 000 исходных строк, 10 000 путей на каждую ось, 100 000 непустых пересечений, явный предел работы и логической памяти. Минимальная ширина представления — 500 логических пикселей; команды занимают две постоянные строки. Представление допускает до 64 столбцов с подписями и до 100 000 ячеек принятой проекции; на экране Grid материализует только viewport. Раскрытие, превышающее предел, отклоняется до публикации. Поля/подписи проверяются перед изменением дерева. Не поддерживаются удалённые кубы, произвольные формулы, distinct-count, экспорт, диаграммы и запись в агрегаты.

`xaml-form --pivot` использует compiled `PivotWindow.xaml` для формы и Rust API для сводной области. Доступны выборка 100 000 записей, NULL, точные Decimal, фильтр, раскрытие, перенос полей и отдельная таблица исходных записей. Это собственная композиция существующего Grid; отдельный XAML-элемент Pivot не требуется.
