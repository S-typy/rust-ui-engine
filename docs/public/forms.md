# Редакторы, привязки и компоновка форм

Пример [EditorsWindow.xaml](../../examples/xaml-form/EditorsWindow.xaml) объединяет
списки, справочник, встроенные кнопки, числовые и календарные поля с наблюдаемой
моделью. Разметка компилируется в Rust при сборке приложения.

[DataForm](data-form.md) создаёт поля по типизированной схеме источника данных,
сохраняет их одной транзакцией и переставляет без пересоздания редакторов.

```text
cargo run --release --locked -p xaml-form -- --editors
cargo run --release --locked -p xaml-form -- --editors --dark
```

## Выбор из коллекции

`ListBox` поддерживает одиночный и множественный выбор, клавиатурную навигацию,
прокрутку и поиск по первым символам. `ComboBox` открывает список; `IsEditable`
разрешает ввод свободного текста. `LookupEdit` ищет по отображаемым колонкам,
но принимает только значение из справочника. Все три элемента используют
устойчивые ключи: изменение порядка коллекции не меняет выбранный объект.

```xml
<ComboBox ItemsSource="{Binding People}"
          DisplayMemberPath="Name" ValueMemberPath="Id"
          SelectedValue="{Binding Form.Person}" />
```

`ItemsSource` — привязанный список `DataValue`. Строковые элементы сами служат
ключом и подписью. Для объектов пути задают подпись и ключ; ключи должны быть
уникальными, а их значения — строками, числами или логическими значениями.
Модель получает исходное значение ключа, а не строковое представление или индекс.
`SelectedValues` используется с `SelectionMode="Multiple"`; `SelectedValue` —
с одиночным выбором. Потерявший элемент выбор очищается при обновлении коллекции.

Статический список содержит `ListBoxItem Value="..." Content="..."`.
`IsEnabled="False"` исключает пункт из пользовательского выбора.
Статические пункты и `ItemsSource` нельзя задавать одновременно.
В runtime одна коллекция ограничена 100000 пунктами и 16 МиБ суммарного текста.
Списки виртуализируют строки с оценочной либо явно измеренной высотой по ключу.
Ограниченный readonly `ItemTemplate` задаёт представление, `ItemPresentation`
выбирает обычные строки, флажки или радиокнопки. Контракты —
[ListBox](list-box.md) и [виртуализация](virtualization.md).
`ComboBox` и `LookupEdit` поддерживают `SelectionMode="Multiple"`, флажки в popup
и `SelectionPresentation="Tokens"`; значение связывается через `SelectedValues`.
Принятые ключи отделены от черновика выбора и поискового текста. Подробнее —
[ComboBox и токены](combo-box.md).

```xml
<LookupEdit ItemsSource="{Binding People}" DisplayMemberPath="Name"
            ValueMemberPath="Id" SelectedValue="{Binding Form.Person}">
  <LookupEdit.Columns>
    <LookupColumn Field="Name" Header="Имя" Width="180" />
    <LookupColumn Field="Department" Header="Отдел" Width="160" />
  </LookupEdit.Columns>
</LookupEdit>
```

Первая колонка представляет `DisplayMemberPath`, следующие задают дополнительные
поля поиска. При заданном `DisplayMemberPath` её `Field` должен совпадать с этим
путём; иначе компиляция завершается ошибкой. Если путь не задан, используется
`Field` первой колонки. Список закрывается при Escape, потере владельца или фокуса окна;
Escape сохраняет ранее принятое значение. В множественном режиме уход фокуса
подтверждает корректный выбор по `CommitOnLostFocus`.

`SearchColumns="0,2"` ограничивает поиск: 0 означает основную подпись,
следующие индексы — дополнительные колонки; пустой список означает все колонки.
`SearchMode` принимает `Contains` (по умолчанию) или `StartsWith`,
`SearchComparison` — `UnicodeLowercase` (по умолчанию) либо `Ordinal`.
UnicodeLowercase применяет Unicode lowercase независимо от культуры; нормализация,
лингвистическая сортировка и сопоставление без диакритики не выполняются.

## Редакторы значений

| XAML | Значение и поведение |
|---|---|
| `ButtonEdit` | Обычный текст и от одной до восьми встроенных `EditorButton` с зарегистрированными командами |
| `MemoEdit` | Многострочный текст в постоянном всплывающем редакторе; компактная кнопка показывает краткий черновик |
| `SearchBox` | Живой поисковый запрос, подсказки и отдельная команда выполнения поиска |
| `PasswordBox` | Изначально пустое защищённое поле с отдельным доступом к значению |
| `SpinBox` | Конечное число, `Minimum`, `Maximum`, положительный `Increment`, кнопки изменения |
| `NumericEdit` | Точное десятичное nullable значение, культура отображения, шаг и встроенный калькулятор |
| `MaskEdit` | Строковое значение из редактируемых позиций с отдельными литералами и подсказками формата |
| `DateEdit` | Дата григорианского календаря, ручной ввод, всплывающий календарь, границы диапазона |
| `TimeEdit` | Время суток, ручной ввод и шаг кнопками; без часового пояса |
| `DateTimeEdit` | Гражданские дата и время в одном nullable значении; календарь и шаг в секундах |
| `DateRangeEdit` | Упорядоченный включительный диапазон дат |
| `Calendar` | Самостоятельный календарь с одиночным выбором или диапазоном и представлениями дней, месяцев и лет |

Общие параметры редактора — `IsReadOnly`, `MaxLength`, `IsRequired`,
`PlaceholderText`, `CommitOnLostFocus`, сообщение ошибки и оформление TextBox.
Enter подтверждает корректный черновик; Escape восстанавливает принятое
значение. По умолчанию корректный ввод подтверждается при уходе фокуса.
Некорректный ввод остаётся в поле с ошибкой и не удерживает фокус.

```xml
<SpinBox Value="{Binding Quantity}" Minimum="1" Maximum="1000" Increment="1" />
<DateEdit Value="{Binding Date}" Format="dd.MM.yyyy" />
<TimeEdit Value="{Binding Time}" Format="HH:mm" />
<ButtonEdit Text="{Binding Reference}">
  <ButtonEdit.Buttons>
    <EditorButton Content="Выбрать" Command="ChooseReference" Icon="ChevronDown" />
  </ButtonEdit.Buttons>
</ButtonEdit>
<MemoEdit Text="{Binding Notes}" PopupWidth="480" PopupHeight="300" />
```

### Точный числовой редактор

`NumericEdit` использует `DecimalValue` с коэффициентом `i128` и масштабом
до 28 знаков; значение не проходит через `f64`. `Value` binding принимает
`DataValue::String` с канонической десятичной записью либо `Null`. Строка использует
точку, без группировки, ведущего плюса, лишних нулей и экспоненты: `"0.1"`,
`"-12.25"`, `"1000"`. Двоичные `DataValue::Number` не принимаются этим binding.
Та же запись применяется к литералам `Value`, `Minimum`, `Maximum`, `Increment`.

```xml
<NumericEdit Value="{Binding Amount}" Minimum="0" Maximum="100000000000000000"
             Increment="0.01" Precision="2" Culture="ru-RU"
             UseGrouping="True" ShowCalculator="True" AllowEmpty="True" />
```

`Precision` задаётся от 0 до 28, по умолчанию 2. Границы, шаг и принятое значение
должны точно представляться с этой точностью; скрытое округление значения при
обычном вводе не выполняется. По умолчанию границы — ±10¹⁵, шаг — 1. `AllowEmpty`
по умолчанию `True`; при `False` требуется начальное `Value` или его binding.
Пустое значение без binding задаётся отсутствием атрибута `Value`.

`Culture` поддерживает `ru-RU`, `en-US`, `ar-SA`; по умолчанию `ru-RU`.
`UseGrouping` управляет группировкой отображаемого числа, по умолчанию `False`.
Отображение использует фиксированное число дробных знаков, а storage строка
содержит нормализованное значение. При изменении культуры и точности сохраняется
точное принятое число; незавершённый черновик сначала нужно подтвердить либо
отменить. Настройки Rust — `NumericEditSettings`; `numeric_value` и
`set_numeric_value` используют `Option<DecimalValue>`.

Кнопка калькулятора включена по умолчанию (`ShowCalculator`). Его операции
выполняются последовательно слева направо. Результат проходит те же ограничения
диапазона, точности и прикладную валидацию редактора; отмена оставляет исходный
черновик. Калькулятор предоставляет отдельные методы открытия, нажатия клавиши,
применения и отмены; он не является вычислителем произвольных выражений.

### Маска ввода

`MaskEdit.Value` содержит только исходные строковые данные редактируемых позиций.
Литералы, разделители культуры и незаполненные позиции принадлежат отображению;
они не добавляются в binding. `Null` не заменяет пустую строку. `Text` в разметке
не принимается, чтобы не задавать два конкурирующих значения.

```xml
<MaskEdit Mask="LL-0009" Value="{Binding ReferenceCode}"
          Culture="ru-RU" PromptChar="_" AllowEmpty="False" />
```

`Mask` обязателен, ограничен 4096 байтами UTF-8 и 256 редактируемыми позициями.
`0` означает обязательную цифру ASCII, `9` — необязательную; `L/l` — букву,
`A/a` — буквенно-цифровую графему, `X/x` — произвольную печатную графему.
У пар с буквами верхний регистр задаёт обязательную позицию. Обратная косая
черта экранирует следующую графему. Символы `.`, `,`, `/`, `:` задают разделители
десятичной части, групп, даты и времени выбранной культуры. Остальные символы
являются литералами. Это ограниченная маска позиций, без регулярных выражений.

`Culture` поддерживает `ru-RU`, `en-US`, `ar-SA`, по умолчанию `ru-RU`.
`PromptChar` по умолчанию `_`; это один печатный Unicode-символ, который сохраняет
границы соседних графем. Он зарезервирован для пустых позиций и не является
вводимым значением. `AllowEmpty` по умолчанию `True`; при `False` требуется
исходный `Value` либо binding. Привязка `Value` по умолчанию `TwoWay/LostFocus`.

Обычные параметры редактора, оформление, черновик, подтверждение, отмена и
прикладная валидация сохраняются. В Rust `MaskSettings` проверяет и форматирует
storage через `validate_storage`/`format`, а `masked_value` и `set_masked_value`
предоставляют явный доступ к данным без литералов. Перед созданием дерева адаптер
формы проверяет категории и обязательность позиций исходного значения.

### Многострочный редактор

`MemoEdit` сохраняет один многострочный документ при каждом открытии. `Text`
поддерживает тот же binding, валидацию, `MaxLength` по графемам и разделение
черновика с принятым значением, что и обычный редактор. Перевод строки считается
графемой. Enter вставляет строку; Ctrl+Enter и кнопка подтверждения принимают
корректный текст и закрывают popup. Ошибка оставляет popup открытым. Escape
сначала отменяет незавершённую композицию IME, а следующее нажатие отменяет
черновик и закрывает popup. Переход между редактором и кнопками popup не
подтверждает текст. При внешнем уходе фокуса действует `CommitOnLostFocus`;
некорректный черновик сохраняется для следующего открытия.

Размер popup по умолчанию — 480×300 логических пикселей. `PopupWidth` принимает
конечные значения 160–16384, `PopupHeight` — 120–16384; фактическая поверхность
ограничивается окном. Режим `IsReadOnly` разрешает открыть текст, выделять и
копировать, но блокирует пользовательское редактирование. В Rust `memo_edit`
возвращает `MemoEdit` с постоянными `container`, `editor`, `popup`,
`apply_button` и `cancel_button`. Методы `open_memo`, `close_memo`, `commit_memo`,
`cancel_memo`, `memo_is_open` принимают этот handle; `memo_parts(container)`
возвращает его для существующего владельца. `composite_editor` разрешает
привязку `Text` к реальному документу.

### Защищённое поле

`PasswordBox` создаётся пустым. XAML не принимает `Text`, `Password`, `Value`,
их bindings или начальный текст внутри элемента. Значение передаётся только
явными Rust-методами `set_password_value`, `password_value` и
`take_password_value`; оно не является обычным `TextBox`-документом и не входит
в `TextChanged` либо `EditEvent`.

```xml
<PasswordBox x:Name="AccountPassword" AutomationName="Пароль учётной записи"
             MaxLength="256" AllowPaste="True" AllowReveal="True"
             RevealDurationMs="3000" PlaceholderText="Пароль" />
```

`MaxLength` ограничивает число графем значением 0–4096; значение по умолчанию —
256, ноль запрещает непустой ввод. `IsReadOnly`, `AllowPaste`, `AllowReveal`
задают правила ввода. `RevealDurationMs` — целое число 1–10000, по умолчанию
3000; раскрытие также прекращается при потере фокуса, отключении и новом вводе.
Доступны обычные размеры, выравнивание, `FontSize`, `Padding`, `CornerRadius`,
`BorderThickness`, основные brushes, `PlaceholderForeground` и `SelectionBrush`.
Привязки разрешены только для `IsEnabled`, `Visibility`, `Width` и `Height`.
Шаблон контрола и вложенное содержимое не поддерживаются.

Защищённое поле не публикует значение в accessibility или обычной диагностике.
Явно полученный `PasswordRef`/`PasswordValue` скрывает текст в `Debug`;
приложение само отвечает за копии после `expose_secret`. Эти типы не обещают
закреплённой или гарантированно очищенной памяти.

### Кнопки внутри редактора

`EditorButton` требует зарегистрированный `Command` и непустой доступный
`Content`, даже если вместо подписи видна иконка или шаблон. Кнопки входят в
одну сессию с редактором: переход фокуса на них не подтверждает черновик.
Порядок обхода клавишей Tab соответствует видимому порядку. Enter и Space
активируют выбранную кнопку через общий реестр команд.

| Свойство | По умолчанию | Контракт |
|---|---|---|
| `Placement` | `Trailing` | `Leading` размещает до текста, `Trailing` после; внутри стороны сохраняется порядок объявления |
| `Width` | `30` | Предпочтительная ширина в логических пикселях, конечное число в `(0, 1024]` |
| `IsVisible` | `True` | Скрытая кнопка не занимает место и не получает ввод |
| `IsEnabled` | `True` | Локальная доступность дополнительно ограничена владельцем и командой |
| `IsEnabledWhenReadOnly` | `False` | Разрешает команду при чтении; встроенное Rust-действие `Clear` всегда заблокировано при чтении |
| `IsTabStop` | `True` | Участие в последовательном обходе клавишей Tab |
| `ContentTemplate` | Нет | Отдельный декоративный экземпляр `DataTemplate` вместо стандартной подписи/иконки |

В узком редакторе кнопки пропорционально уменьшаются, оставляя до 24 пикселей
для текста; дочернее содержимое ограничено общей рамкой. Автоматическая высота
следует текущей теме и плотности, явно заданная высота сохраняется. В Rust
`EditorControl::buttons` содержит стабильные идентификаторы. Настройки изменяются
через `set_editor_button_settings(button, EditorButtonSettings)`; неверные
значения отклоняются до изменения дерева. `set_editor_button_content` принимает
готовое постоянное неинтерактивное поддерево. Замена сохраняет команду, подпись
доступности, подсказку и редактор; прежнее поддерево отсоединяется для повторного
использования.

```xml
<Window.Resources>
  <DataTemplate x:Key="ChooseFace">
    <StackPanel Orientation="Horizontal" Spacing="4">
      <Icon Symbol="FolderOpen" Width="16" Height="16" />
      <TextBlock Text="{Binding ChooseCaption}" />
    </StackPanel>
  </DataTemplate>
</Window.Resources>
<ButtonEdit Text="{Binding Reference}">
  <ButtonEdit.Buttons>
    <EditorButton Content="Выбрать документ" Command="ChooseReference"
                  Placement="Leading" Width="120" IsEnabledWhenReadOnly="True"
                  ContentTemplate="{StaticResource ChooseFace}" />
  </ButtonEdit.Buttons>
</ButtonEdit>
```

Допустима также форма `<EditorButton.ContentTemplate>` с единственным визуальным
корнем. Шаблон имеет отдельное пространство имён и лексическую область ресурсов,
наследует `DataContext`; внешняя подпись доступности остаётся у кнопки. Разрешены
текст, иконки, изображения и контейнеры без взаимодействия, с привязками только
`OneWay`/`OneTime`. Вложенные редакторы, кнопки и записывающие привязки отклоняются.
Корень представления кнопки по умолчанию центрируется по обеим осям, в том числе
при замене во время работы. Явные `HorizontalAlignment` и `VerticalAlignment`
сохраняются. `CommonProperties` хранит признаки явно заданного выравнивания,
чтобы отличать `Stretch` из разметки от значения по умолчанию.
Общие правила ресурсов и шаблонов описаны в [styles-and-templates.md](styles-and-templates.md).

### Дата, время и календарь

Дата по умолчанию отображается как `ДД.ММ.ГГГГ`, время — `ЧЧ:ММ`.
Также поддерживаются `yyyy-MM-dd` и `HH:mm:ss`. Значения `Value`, `Minimum`,
`Maximum` в разметке и модели используют ISO: `2026-10-15`, `09:30:00`.
Пустая дата или время представлены `DataValue::Null`; `AllowEmpty="False"`
запрещает пустое значение и требует начальный литерал либо binding. Общая
валидация `IsRequired` также может запрещать подтверждение пустого поля.
Диапазон дат — годы 1–9999, включая проверку високосных лет. Скрытые секунды
сохраняются в принятом значении и при подтверждении прежних часов и минут;
изменение формата не обнуляет их. Ввод других часов или минут без секунд
устанавливает секунды в ноль.
Пустой календарь открывается на текущей дате UTC, ограниченной допустимым
диапазоном; это не устанавливает значение поля. Шаг времени по умолчанию равен
минуте. `TimeStep` задаёт 1–86400 секунд для `TimeEdit` и `DateTimeEdit` независимо
от отображения секунд. `ShowSeconds` включается явно; у `TimeEdit` также сохранён
`Format="HH:mm:ss"`. Противоречащие друг другу `Format` и `ShowSeconds` отклоняются.

```xml
<DateTimeEdit Value="{Binding Meeting}" Minimum="2026-01-01T00:00:00"
              DateFormat="dd.MM.yyyy" ShowSeconds="True" TimeStep="30" />
<DateRangeEdit Value="{Binding Vacation}" Format="dd.MM.yyyy"
               Minimum="2026-01-01" Maximum="2026-12-31" />
<Calendar Value="{Binding SelectedDates}" SelectionMode="Range"
          DisplayDate="2026-10-01" View="Days" />
```

`DateTimeEdit.Value` — каноническая строка `YYYY-MM-DDTHH:MM:SS` либо `Null`.
Это гражданские дата и время: смещение, часовой пояс, переходы летнего времени
и дробные секунды не включены. `Minimum` и `Maximum` используют тот же формат.
`DateFormat` отвечает только за отображение даты.

`DateRangeEdit.Value` в binding — объект `{"start":"2026-10-01","end":"2026-10-07"}`
либо `Null`; начало не может быть позже конца. Литерал XAML записывается как
`Value="2026-10-01/2026-10-07"`. `Minimum` и `Maximum` ограничивают обе даты.

`Calendar.SelectionMode` — `Single` по умолчанию или `Range`; `Value` имеет
соответственно ISO-строку либо объект диапазона. Статический диапазон использует
тот же литерал со слешем. `DisplayDate` выбирает показываемую дату без изменения
выбора. `View="Days|Months|Years"` задаёт начальное представление. `IsReadOnly`
запрещает пользовательское изменение выбора. Calendar не создаёт текстовый
черновик: его `Value` binding по умолчанию `TwoWay/PropertyChanged`, тогда как
редакторы даты, времени и диапазона используют `TwoWay/LostFocus`.

Подробные Rust API, правила календарного выбора и поведение всплывающих
редакторов описаны в [редакторах даты и времени](date-time-editors.md).

## Наблюдаемая модель

`BindingContext` хранит дерево `DataValue`: объект, список, строку, конечное
число, логическое значение или null. Пути поддерживают вложенные поля и индексы:
`Customer.Name`, `Rows[0].Amount`. Изменения выполняются в UI-потоке; скрытого
цикла событий и фоновой диспетчеризации нет.

```rust
use rust_desktop_ui_controls::{BindingContext, DataValue};

let mut model = BindingContext::new(DataValue::object([
    ("Name", DataValue::from("Документ")),
    ("Quantity", DataValue::from(12.0)),
]))?;
model.set("Name", "Новый документ".into())?;
model.set_many([("Name", "Заказ".into()), ("Quantity", 24.0.into())])?;
# Ok::<(), Box<dyn std::error::Error>>(())
```

`set_many` атомарно проверяет итоговое дерево. `ValueSchema` описывает допустимые
типы, а `BindingValidator` проверяет модель целиком, включая зависимости полей.
Неуспешная проверка не меняет данные или ревизию. Поля не создаются неявно;
для изменения структуры заменяется соответствующий объект или список.
Копия callback валидатора разделяет его реализацию через `Rc`.

`revision` и `changes_since` позволяют нескольким представлениям независимо
наблюдать один контекст. История ограничена 256 пакетами; отсутствующая история
требует повторного чтения значений. Ограничения дерева — 100000 узлов, глубина
64, 4 МиБ текста. `ControlBindings` сопоставляет свойства с данными, не потребляя
очереди событий приложения.

## Контракты привязок

```xml
<Grid DataContext="{Binding Customer}">
  <TextBox Text="{Binding Name, Mode=TwoWay, UpdateSourceTrigger=LostFocus}" />
</Grid>
```

`DataContext` задаёт путь относительно унаследованного контекста. Замена объекта
по этому пути обновляет потомков. `ElementName` выбирает именованный элемент
той же смонтированной формы; `Path` тогда означает его поддерживаемое свойство.
Явные циклы таких зависимостей отклоняются.

| Mode | Направление |
|---|---|
| `OneWay` | Модель → свойство |
| `TwoWay` | Модель ↔ свойство |
| `OneTime` | Однократное начальное чтение модели |
| `OneWayToSource` | Свойство → модель, включая начальное значение |

Для `Text` редакторов и типизированного `Value` по умолчанию используется
`TwoWay` / `LostFocus`. Этот trigger публикует принятое значение, поэтому Enter
также обновляет модель. Выбор и `IsChecked` используют `TwoWay` /
`PropertyChanged`; отображаемый текст — `OneWay`. `PropertyChanged` у редактора
наблюдает черновик, исключая незавершённый IME preedit. `Explicit` ждёт
`ControlBindings::update_sources`.

Поддерживаемые свойства: `Text`, `Content`, `Value`, `SelectedValue`,
`SelectedValues`, `ItemsSource`, `IsChecked`, `IsEnabled`, `IsReadOnly`,
`Visibility`, `Width`, `Height`, `PlaceholderText`. В разметке доступность
привязки дополнительно проверяется для конкретного элемента. `Visibility`
принимает `Visible`, `Hidden`, `Collapsed`: Hidden сохраняет место в компоновке,
Collapsed убирает его до восстановления видимости. В привязке используются эти
строки; логические true/false соответствуют Visible/Hidden. Min/max размеров,
`AutomationName` и `ToolTip` пока задаются
литералами. Путь XAML содержит ASCII-идентификаторы и неотрицательные индексы;
обращения к полям через кавычки не разрешены. Вычисления задаются отдельной ограниченной формой MultiBinding, описанной ниже.

Конвертеры регистрируются приложением в `BindingConverterRegistry`.
Для записи в модель нужен обратный конвертер. `Converter=Name` выбирает его
по имени; `FallbackValue` задаёт резервное значение при ошибке чтения/конверсии.
Ошибки доступны через `drain_diagnostics`; ошибки бизнес-проверки показываются
редактором до принятия значения. Изменение постороннего поля модели сохраняет
черновик, undo и IME-состояние. При одновременном изменении одного свойства
в модели и интерфейсе приоритет имеет новое значение модели.

Для общего ItemsSource можно зарегистрировать наблюдаемую коллекцию через
`BindingContext::register_collection`. ListBox, ComboBox и LookupEdit принимают
изменения состава и полей при обычном `sync`, сохраняя выбор по ключу.
Привязки используют журнал изменений и не перечитывают неизменённые списки.
Контракт и ограничения проекции — [наблюдаемые коллекции](observable-collections.md).

## Компоновка

| Контейнер | Семантика |
|---|---|
| `StackPanel` | Последовательная вертикальная или горизонтальная компоновка |
| `Grid` | Строки и колонки `Auto`, пиксели, `*`, `2*`; размещение и spans |
| `WrapPanel` | Перенос элементов на следующую строку или колонку |
| `DockPanel` | Последовательное резервирование краёв, `LastChildFill=True` по умолчанию |
| `Border` | Один ребёнок, padding, фон, граница и скругление |
| `GroupBox` | Заголовок и одно содержимое; Card, Outline, Plain, Standard; необязательное сворачивание |
| `Expander` | Сворачиваемая группа; поддерево и привязки сохраняются |
| `TabbedGroup` | Несколько GroupTab с сохранением неактивных страниц; SelectedIndex |
| `ScrollViewer` | Один ребёнок, две оси, отсечение и полосы прокрутки |

```xml
<Grid Spacing="12">
  <Grid.RowDefinitions>
    <RowDefinition Height="Auto"/><RowDefinition Height="*"/>
  </Grid.RowDefinitions>
  <Grid.ColumnDefinitions>
    <ColumnDefinition Width="160"/><ColumnDefinition Width="*"/>
  </Grid.ColumnDefinitions>
  <TextBlock Text="Название" VerticalAlignment="Center" />
  <TextBox Grid.Column="1" Text="{Binding Name}" />
  <ScrollViewer Grid.Row="1" Grid.ColumnSpan="2" HorizontalScrollBarVisibility="Disabled">
    <StackPanel><TextBlock Text="Содержимое" /></StackPanel>
  </ScrollViewer>
</Grid>
```

Индексы Grid начинаются с нуля, spans положительные. Ось без явных tracks
растягивает единственную ячейку. Общие свойства: `Width`, `Height`,
`MinWidth`, `MinHeight`, `MaxWidth`, `MaxHeight`, `Margin`, `Visibility`,
`HorizontalAlignment`, `VerticalAlignment`. Приоритет явного размера сохраняется.
Выравнивание принимает `Left`/`Right` или `Top`/`Bottom`, `Center`, `Stretch`.
`Width="Auto"` и `Height="Auto"` используют правила автоматического размера
контрола. Явные размеры положительны, min/max могут быть нулевыми; значения
ограничены 16384 логическими пикселями. В XAML отступы неотрицательны.
Корневые Grid, Border, DockPanel и ScrollViewer с автоматической высотой и
`VerticalAlignment="Stretch"` занимают доступную высоту формы.

`DockPanel.Dock` принимает `Left`, `Top`, `Right`, `Bottom`; последняя область
по умолчанию занимает остаток. Разрешено до 48 детей одного DockPanel;
вложенные служебные контейнеры учитываются в пределе глубины layout.
`DockPanel` не является docking workspace.
Группы и их `Header`/`IsExpanded`/`SelectedIndex` bindings описаны в [отдельном контракте](groups.md).
Для перемещаемых панелей и отдельных окон используется [DockWorkspace](docking.md).

ScrollViewer использует `Auto`, `Visible`, `Hidden`, `Disabled` отдельно для
каждой оси. `Hidden` скрывает полосу, сохраняя прокрутку; `Disabled` отключает
прокрутку и ограничивает содержимое размером viewport по этой оси. Полосы
расположены поверх содержимого. Поддерживаются wheel, клавиши, track и thumb.
Обе оси по умолчанию используют `Auto` в XAML; задайте `Disabled` явно для
растягивания содержимого по ширине окна. Скругление Border относится к его
фону и рамке: отсечение дочернего содержимого остаётся прямоугольным.

Профиль форм поддерживает только перечисленные элементы и свойства. Общие
шаблоны, динамическая регистрация свойств, коллекционные шаблоны и произвольная
локаль форматирования не поддерживаются. Геометрия и состояние проверяются
unit/integration-тестами; это не заменяет проверки native IME и screen reader.

В Rust `EditorControl` раскрывает идентификаторы контейнера, текстового поля и
кнопок для настройки. Удаление всего редактора выполняется через `container`.
Отдельное удаление обязательного `editor` или `ListBox.content` отклоняется
до изменения дерева; необязательную встроенную кнопку можно удалить отдельно.


## Привязки нескольких источников и выражения

`BindingSource::Multi(Vec<BindingInput>)` передаёт упорядоченный `DataValue::List`
зарегистрированному конвертеру. `BindingSource::Expression` вычисляет
`BindingExpression` над теми же зависимостями. Каждый вход — путь модели или
свойство другого элемента. Доступны только `OneWay` и `OneTime`: неоднозначной
обратной записи сразу в несколько источников нет.

```xml
<TextBlock Text="{MultiBinding Paths='Quantity;Price', Expression='concat(&quot;Total: &quot;, $0 * $1)'}" />
```

`Paths` разделяются `;`. `#Other.Text` выбирает свойство именованного элемента.
Вместо `Expression` можно задать `Converter=Name`; он получает список значений.
В Rust `BindingSource::Expression` может дополнительно передать вычисленный
результат converter. В XAML `Expression` и `Converter` взаимоисключающие.
Путь модели наследует `DataContext`. Циклы с участием любого ElementName-входа
отклоняются до первого переноса значений. Изменения посторонних полей не
перечитывают выражение и сохраняют черновики редакторов.

Грамматика содержит `$0`–`$31`, конечные числовые литералы, строки без escape,
`true`, `false`, `null`, скобки, `+ - * / %`, сравнения, `&& || !`, `??`,
`if(condition, yes, no)`, `concat(...)` и `len(...)`. Операторы типизированы;
неявного преобразования строки в число нет. Булевы операторы, `if` и `??`
вычисляют только выбранную ветвь. `len` считает графемы строки либо элементы
списка. Вызовов методов, файлов, сети или произвольного Rust-кода нет.
Лимиты: 4096 байт исходного выражения, 256 узлов, 32 уровня синтаксической
вложенности, 32 входа, 65536 байт сформированной строки. Ошибки содержат позицию
в выражении; compiled binding сохраняет исходную строку/колонку XAML для preflight.

`SelectedKey` подключает стабильный строковый ключ RadioGroup. `IsChecked`
принимает `Null` только у локального трёхсостоянийного переключателя. Slider
поддерживает `Value`, RangeSlider — `LowerValue`/`UpperValue`, ProgressBar —
`IsIndeterminate`. Два привязанных края RangeSlider читаются и применяются
одной операцией: модель не выставляет временно перевёрнутый диапазон.
Параметры конструкции, например тип элемента, состав дочерних элементов,
рецепты изображения и настройки шаблона, задаются до монтажа.

## Проверки зависимых полей и асинхронное подтверждение

`CrossFieldRule` содержит список `BindingPath`, булево `BindingExpression` и
сообщение ошибки. `BindingValidator::from_rules` создаёт политику из 1–128
правил. Все выражения проверяют итоговую модель `set_many`; при ошибке значения
и ревизия сохраняются. Небулевой результат правила считается ошибкой настройки.
Произвольный синхронный `BindingValidator` также остаётся доступным.

`Controls::set_async_editor_validator` устанавливает `AsyncEditorValidator`.
Его worker получает `EditorValidationRequest`: неизменяемый draft, контекст,
его ревизию, `UiCulture` и cooperative cancellation token. `commit_edit`
возвращает `CommitOutcome::Pending`; принятое значение и модель до результата
не меняются. Повторный Enter во время той же проверки не создаёт второй worker.
Ошибка сохраняет черновик; успешный ответ повторно проверяется синхронной
политикой и принимается в UI-потоке ровно один раз. Уход фокуса не блокируется.

`poll_editor_validation` вызывается внутри `Controls::update`. Для sleeping
host задаётся `set_editor_validation_waker`; callback только планирует UI-кадр.
Draft mutation, IME preedit, Escape, замена value/validator/settings, удаление
элемента, смена контекста или культуры отменяют актуальность старой проверки.
Валидатор обязан периодически проверять `cancellation.is_cancelled()`: принудительно
останавливать поток библиотека не пытается. Пока старый worker не завершился,
он продолжает занимать слот. Panic превращается в обычную диагностируемую ошибку.

`set_editor_validation_context` заменяет явный снимок связанных данных и культуру.
Приложение обновляет его до UI update; `ControlBindings` также отменяет pending
проверки при новой ревизии модели. `PropertyChanged` и `Explicit` не публикуют
непроверенный draft асинхронного редактора. Программная загрузка
`set_editor_value` остаётся синхронным валидируемым присвоением модели;
асинхронная политика применяется к пользовательскому подтверждению.

Лимиты: 1024 зарегистрированных async редактора, 16 workers, очередь 32 ответов,
64 МиБ расчётного объёма удерживаемых контекстов, 4096 байт UTF-8 диагностики.
Глубина, число узлов и размер текста каждого контекста проверяются как DataValue.
Хранилище, HTTP-клиент и политика timeout принадлежат приложению.
[Культура и переводы](localization.md) не меняют формат хранения данных.
