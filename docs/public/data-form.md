# DataForm

`DataForm` создаёт сохраняемую форму по `TableSchema` и строке зарегистрированного
`DataSource`. Каждое поле имеет подпись, редактор, исходное значение и стабильные
идентификаторы. Приложение хранит `DataForm` рядом с `Controls`, вызывает `update`
после ввода и явно выбирает момент сохранения или обновления данных.

Пример: `cargo run --release -p xaml-form -- --data-form`.
Он использует коллекцию Rust в памяти; команды сохранения изменяют эту коллекцию.
«Изменить имя в источнике» показывает конфликт внешней записи с локальным вводом.

```rust
let mut form = DataForm::mount(
    &mut ui, parent, source, row_key,
    DataFormSettings::default(), &DataFormFactories::default(), layout,
)?;
let editor = form.field_editor("name").unwrap();
// Обработчик команды «Сохранить»:
let outcome = form.commit(&mut ui)?;
```

`container` обозначает корень формы; `summary` — общую строку ошибок.
`field(name)` возвращает владельца редактора, `field_editor(name)` — его текстовую
часть либо checkbox. Удаление всего контейнера выполняется через `Controls`;
удаление или перенос обязательной части обнаруживается до следующей операции
формы. Уничтожение Rust handle само по себе не удаляет дерево.

## Metadata и редакторы

Пустой `DataFormSettings.fields` создаёт все поля в порядке схемы. Непустой список
задаёт явное подмножество и порядок. `DataFormField` содержит `field`, необязательную
`label`, `visible`, `read_only` и имя `editor`. Без label используется заголовок
схемы. Запрет редактирования схемы, всей формы, поля или текстовой фабрики сохраняется.

| Тип поля | Редактор Auto | Представление |
| --- | --- | --- |
| Bool | CheckBox | Nullable использует Indeterminate для NULL |
| Integer | Numeric | Точный i64, включая MIN/MAX, без преобразования через f64 |
| Decimal | Numeric | Точный DecimalValue, до 28 дробных знаков |
| Date | Date | ДД.ММ.ГГГГ, календарь |
| Time | Time | ЧЧ:ММ:СС, секунды сохраняются |
| Text | Text | TextBox, включая многострочный текст |
| Real | Text | Строгий конечный f64 через парсер схемы |
| Binary | Text | Шестнадцатеричная запись с префиксом `0x` |

Для nullable полей, кроме Bool, рядом с редактором показан отдельный переключатель
`NULL`. Он явно отличает отсутствие значения от пустого текста. Пока NULL включён,
редактор недоступен; снятие переключателя позволяет изменить значение. `false`
и NULL у Bool также различаются. `set_field_value` загружает локальное значение,
`set_field_null` задаёт NULL. Эти методы не записывают источник; read-only metadata
всё равно запрещает сохранить изменённое значение.

Встроенные имена фабрик: `Auto`, `Text`, `Numeric`, `Date`, `Time`, `CheckBox`.
`DataFormFactories::register` добавляет именованную настройку существующего
редактора: `DataFormEditorFactory::{Text,Numeric,Date,Time,CheckBox}`. Имена уникальны,
содержат 1…64 ASCII-буквы, цифры или `_.-`; допускается 64 пользовательских рецепта.
Встроенные имена нельзя заменять. Типизированный адаптер выбирается вместе с
рецептом; произвольные виджеты и callbacks внутри транзакции не создаются.

До монтажа и программной загрузки проверяется точное преобразование значения
в представление и обратно. Несовместимые типы, недостаточная точность, диапазон,
лимит текста либо скрытые ненулевые секунды отклоняются без замены значения.
Nullable Numeric/Date/Time требуют рецепт с `allow_empty=true`. Текстовые пределы
и ограничения формирования текста остаются общими для редакторов.

Типизированные настройки Numeric/Date/Time принадлежат выбранному рецепту.
Их внешняя замена обнаруживается до операций формы и требует явного повторного
монтажа; форматирование и разбор не продолжаются с разными настройками.

## Сохранение и конфликты

`value` читает типизированный локальный ввод; `is_dirty` учитывает отличие от
исходного значения, незавершённый текст и композицию. Невалидный текст сохраняется
в редакторе и считается изменением.

`commit` проверяет все поля и локальные валидаторы, затем выполняет один
`DataSource::write_batch` с `DataWrite::Update` для изменённых полей и ожидаемыми
исходными значениями. Адаптер должен поддерживать атомарное обновление. Отдельные
записи не используются как замена транзакции. Ошибка разбора, проверки или конфликт
не записывает часть полей и не стирает ввод.

`DataFormCommit` различает `Saved`, `Unchanged`, `Invalid(issues)`, `Pending` и
`Conflict(message)`. `Pending` означает активную IME-композицию либо асинхронную
проверку; приложение повторяет команду после завершения. Ошибки адаптера и
некорректные операции возвращаются через `ControlError`.

Локальное подтверждение редактора и сохранение формы — отдельные действия.
Некоторые редакторы могут подтвердить ввод до последующей ошибки Save; исходное
значение формы при этом не меняется, текст остаётся на месте, форма остаётся dirty.
После успешной записи обновляются только исходные значения формы; повторных
валидаторов или загрузчиков редакторов после изменения источника нет.

`refresh` читает текущий принятый snapshot источника, обновляет чистые поля и
сохраняет dirty поля. Если источник изменил такое поле, появляется конфликт.
I/O адаптера выполняется отдельно через `DataSource::refresh` или `synchronize`.
`revert` явно загружает текущую строку и отбрасывает локальный ввод. Загрузка
проверяется отдельно для каждого поля: отклонённое поле сохраняет предыдущий
текст и получает диагностическое сообщение. Изменение схемы требует явного
повторного монтажа; удалённая строка не превращается автоматически в новую.

## Компоновка

`arrangement` возвращает полный порядок полей с видимостью. `arrange` принимает
каждое сгенерированное поле ровно один раз и общую ширину подписей; применяет
изменения одной операцией дерева. Перестановка и скрытие не пересоздают редакторы
и сохраняют текст, историю и IDs. Фокус остаётся в видимом редакторе; скрытое
содержимое следует общим правилам фокуса UI.

Форма использует обычные Grid-строки и вертикальный контейнер. `LabelWidth`
ограничен 0…4096, `RowGap` — 0…256 логических пикселей; максимум 128 полей.
Прокрутка задаётся внешним ScrollViewer. Интерактивный дизайнер расположения,
автоматическое сохранение настроек на диск и reflection типов не выполняются.

## Compiled XAML

```xml
<DataForm x:Name="PersonForm" DataSource="People" RowKey="7"
          LabelWidth="180" RowGap="8">
  <DataForm.Fields>
    <DataFormField FieldName="name" Label="Имя" />
    <DataFormField FieldName="count" Label="Количество" Editor="Numeric" />
    <DataFormField FieldName="internal" IsVisible="False" IsReadOnly="True" />
  </DataForm.Fields>
</DataForm>
```

`DataSource` — имя, зарегистрированное в Rust через `register_data_source`;
`RowKey` — signed i64 (по умолчанию 0). Без `DataForm.Fields` поля берутся из схемы.
Metadata не содержит bindings: источник, строка, фабрики и расположение задаются
явно. XAML использует встроенные фабрики; именованные пользовательские рецепты
передаются через Rust API. Общие Width/Height/Visibility/IsEnabled bindings
поддерживаются. Команды Save/Refresh/Revert остаются обработчиками приложения.

Связанные контракты: [данные](data.md), [точные числа](numeric-editors.md),
[дата и время](date-time-editors.md), [редактирование текста](text-editing.md).

Auto Decimal uses `trim_trailing_zeros=true` for compact display while retaining precision 28. Values with additional fractional digits remain exact; integer/grouping zeros are preserved. Explicit Numeric recipes keep their configured display policy.
