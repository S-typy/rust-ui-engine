# Группы и раскрывающиеся секции

`GroupBox` объединяет содержимое под заголовком. `Expander` добавляет
раскрытие и сворачивание той же области. Оба элемента поддерживают вложенные
контейнеры, редакторы и привязки, а оформление следует текущей светлой или
тёмной теме.

Пример [GroupsWindow.xaml](../../examples/xaml-form/GroupsWindow.xaml):

```text
cargo run --release --locked -p xaml-form -- --groups
cargo run --release --locked -p xaml-form -- --groups --dark
```

## XAML

```xml
<GroupBox Header="Документ" Appearance="Card" Padding="16"
          DataContext="{Binding Document}">
  <StackPanel Spacing="12">
    <TextBox Text="{Binding Title}" />
    <Expander Header="Дополнительные параметры"
              IsExpanded="{Binding ShowDetails}" Appearance="Outline">
      <StackPanel Spacing="8">
        <DateEdit Value="{Binding Date}" />
        <TextBox Text="{Binding Note}" />
      </StackPanel>
    </Expander>
  </StackPanel>
</GroupBox>
```

| Свойство | Контракт |
|---|---|
| `Header` | Текст заголовка, не более 4096 байт UTF-8; пустая строка разрешена |
| `Appearance` | `Card` по умолчанию, `Outline` или `Plain` |
| `Padding` | Отступ содержимого; по умолчанию 16 логических пикселей со всех сторон |
| `IsExpanded` | Только Expander; по умолчанию `True` |

`Card` использует отдельную поверхность с рамкой и скруглением; `Outline` —
контурную группу; `Plain` — заголовок без внешней рамки. Цвета выбираются из
текущей темы. Смена темы не пересоздаёт содержимое.

Внутри допускается один элемент или пустое содержимое. Для нескольких полей
используйте StackPanel, Grid либо другой контейнер. Общие свойства размеров,
выравнивания, Grid-размещения, `Visibility`, `IsEnabled`, `AutomationName`
и `DataContext` работают как у остальных элементов формы.

`Header` допускает привязку с направлением `OneWay` по умолчанию.
`IsExpanded` использует `TwoWay` / `PropertyChanged`: изменение модели раскрывает
секцию, а действие пользователя обновляет модель. Оба свойства доступны через
`ElementName`. Контекст данных наследуется содержимым группы; группа сама по
себе не создаёт отдельного пространства XAML-имён.

## Поведение

Обычный GroupBox не создаёт дополнительную остановку Tab. Заголовок Expander
доступен с клавиатуры: Enter или Space переключает раскрытие. Состояние и
действия раскрытия передаются в дерево доступности.

Сворачивание исключает содержимое из компоновки и взаимодействия, сохраняя
его WidgetId, документы, выбор и привязки. Это не удаление и не повторный
монтаж. Состояние вложенного Expander также сохраняется. При автоматической
высоте секция сжимается до заголовка; явно заданная внешняя высота сохраняется.
Корневой GroupBox с автоматической высотой и `VerticalAlignment="Stretch"`
заполняет доступную высоту формы. Корневой Expander сохраняет автоматическое
измерение, чтобы свёрнутая секция занимала только высоту заголовка.

Привязки продолжают получать изменения модели, когда секция свёрнута.
Клик по заголовку проходит обычную смену фокуса и применяет
`CommitOnLostFocus` редактора. Программное сворачивание сохраняет обычный
черновик без автоматического подтверждения и отменяет незавершённый IME preedit.
Если фокус находился в содержимом, он переводится на доступный заголовок.
Сворачивание не добавляет отдельной транзакции подтверждения всей группы.

## Rust API

`Controls::group_box` принимает `GroupSettings` и `LayoutStyle`, возвращая
`GroupBox` с идентификаторами `container`, `header` и `content`.
`Controls::expander` дополнительно принимает начальное состояние раскрытия
и возвращает такие же части в `Expander`. Дочерние контролы создаются в `content`.

`GroupSettings` задаёт `header`, `appearance: GroupAppearance` и `padding`.
Заголовок меняется через `set_group_header`, настройки — через
`set_group_settings`. `expander_expanded` читает состояние, а
`set_expander_expanded` меняет его. Все эти операции используют идентификатор
контейнера. Привязки представлены `BindingProperty::Header` и
`BindingProperty::IsExpanded`.

Для удаления всей группы используйте `container`. Удаление обязательного
служебного заголовка или контейнера содержимого отдельно отклоняется до
изменения дерева; обычные пользовательские дети удаляются независимо.

Профиль поддерживает текстовые заголовки и вертикальное раскрытие вниз.
Произвольные HeaderTemplate, анимации раскрытия, accordion-взаимоисключение
и генерация полей по модели не входят в этот контракт.
