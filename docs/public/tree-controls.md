# Иерархические элементы формы

`Controls::tree_view` и `Controls::tree_grid` предоставляют виртуализированную
иерархию с общим источником, моделью колонок и семантикой. Данные принадлежат
приложению, идентичность строки задаётся `RowKey(u64)`, ячейки — `ColumnId(u64)`.
Содержимое ячеек отображается как текст; host не открывает редакторы ячеек.

## Источник и регистрация

`TreeSourceHandle::new(source)` принимает реализацию `TreeDataSource`.
`TreeSourceHandle::from_shared(Rc<RefCell<T>>)` позволяет приложению обновлять
тот же источник и передавать его нескольким независимым представлениям.
Перед обращением к Controls нужно освободить заимствования источника.
Host проверяет доступность через `try_borrow_mut` и возвращает ошибку вместо
паники при занятом источнике. Прямые методы `TreeDataSource` без `Result` на
handle требуют соблюдения обычного контракта `RefCell` самим вызывающим кодом.

`IndexedTreeSource::new(Vec<TreeNode>)` строит проверяемый индекс. Каждый узел
содержит key, parent, текстовые cells и `TreeChildren::Known` либо `Unloaded`.
Порядок записей определяет порядок соседей; родитель может идти после ребёнка.
Проверяются все записи, в том числе невидимые ветки: дубликаты, отсутствующие
родители, циклы, глубина выше 256 и несовместимые unloaded-ветки отклоняются.
Пределы: миллион узлов, 64 ячейки на узел, 1 MiB на текст ячейки и 64 MiB
текста на весь источник. `replace`, `replace_children` и `move_rows` сначала
проверяют кандидат, затем изменяют источник и checked revision целиком.
Ошибка, включая переполнение revision, оставляет прежние записи и индекс.

Произвольный `TreeDataSource` предоставляет индексированные `child_at`,
`child_count`, `position`, `parent`, `cell`. Не требуется линейного обхода всех
данных: модель проверяет затронутые пути и материализованные строки. Полную
согласованность невидимых веток такой поставщик обеспечивает сам. Изменение
`revision()` автоматически обновляет host; поставщик с default revision=0
требует явного `tree_refresh` после внешней записи.

## XAML

Приложение до mount вызывает `register_tree_source("Nodes", handle)`.
`Source` — имя регистрации, не отражение типов и не строка запроса.

```xml
<TreeView Source="Nodes" DisplayColumn="0"
          SelectedKey="{Binding SelectedNode}" Height="320" />

<TreeGrid Source="Nodes" AllowNodeDrag="True" IsReadOnly="False"
          SelectedKey="{Binding SelectedNode}" Height="320">
  <TreeGrid.Columns>
    <TreeColumn Id="0" Header="Название" Width="260" IsPinned="True" />
    <TreeColumn Id="1" Header="Состояние" Width="160" />
  </TreeGrid.Columns>
</TreeGrid>
```

TreeView имеет один `DisplayColumn`; TreeGrid требует 1..64 явных TreeColumn.
Иерархический отступ принадлежит первой объявленной колонке, независимо от
последующего reorder. `Id` и `DisplayColumn` в XAML ограничены u32; Rust API
сохраняет полный ColumnId. Колонки имеют Header, Width, MinWidth, MaxWidth,
IsPinned; ширины конечны и удовлетворяют 32 ≤ MinWidth ≤ Width ≤ MaxWidth ≤ 4096.
Прямые TreeColumn и wrapper TreeGrid.Columns поддержаны, смешивание запрещено.

## Выбор и взаимодействие

`TreeControlSettings::selection_mode` и XAML SelectionMode по умолчанию Single.
Multiple включает Ctrl-toggle и Shift-range; без модификаторов выбирается один
узел. `tree_selected_keys` возвращает ключи в числовом порядке.
`set_tree_selected_key` назначает существующий ключ, включая узел под свернутым
предком, без принудительного раскрытия. Неизвестный ключ отклоняется. Скрытые
выбранные ключи переживают collapse и refresh; после удаления записи приложение
явно очищает соответствующий выбор.

SelectedKey binding доступен только при Single: canonical u64 decimal String
либо Null. Все 64 бита сохраняются; Number, `01`, `+1`, отрицательные и дробные
значения отклоняются. Binding по умолчанию TwoWay/PropertyChanged. Валидатор
`set_tree_selection_validator` получает строковые ключи; отказ при pointer,
keyboard или semantic action восстанавливает выбор, фокус и scroll и не
публикует событие. Проверки источника binding добавляются к валидатору host.
`take_tree_selection_changes` выдаёт изменившиеся наборы ключей.

Стрелки вверх/вниз, Home/End/PageUp/PageDown перемещают выбор; вправо раскрывают
ветку или переходят к ребёнку, влево сворачивают её или выбирают родителя.
Enter раскрывает/сворачивает сфокусированный узел; Ctrl+Left/Right перемещает
фокус между колонками в порядке отображения. Колонки поддерживают resize,
reorder и pin; TreeView растягивает единственную колонку по viewport.
Сортировка заголовком делегирована поставщику и может быть отклонена им;
`IndexedTreeSource` не реализует запросы сортировки и фильтрации.

## Перенос и lazy-загрузка

Node drag включается только сочетанием AllowNodeDrag=True и IsReadOnly=False.
ReadOnly ограничивает пользовательское изменение структуры; выбор, раскрытие
и явные вызовы приложения остаются доступны. Перемещение начинается после
5 px, показывает проверенный drop marker и проверяет точку отпускания ещё раз.
Верхняя/нижняя треть строки вставляет до/после, середина переносит в конец
дочернего списка. Descendant/self-drop и неполученный список детей назначения
отклоняются до записи. Escape, capture loss, disable, изменение geometry,
read-only или revision источника отменяют жест. Перетаскивание между отдельными
источниками и окнами не входит в этот контракт.

Программные `tree_move_nodes` и `IndexedTreeSource::move_rows` принимают до 4096
ключей. Перемещение нескольких корней сохраняет запрошенный порядок и их
поддеревья. Поставщик обязан выполнить move атомарно, сохранив корректный граф
и ключи; default implementation возвращает Unsupported без fallback.

Unloaded-узел запускает `request_children` с токеном model/epoch/sequence/parent.
`tree_complete_children` принимает ключи произвольного поставщика;
`tree_complete_indexed_children` атомарно проверяет точный shared source, токен
и новые TreeNode. Stale, foreign и отменённые ответы не изменяют источник.
Ошибка структуры в асинхронном ответе не меняет принятые строки и оставляет
токен для исправленного ответа. Некорректный синхронный Ready завершает запрос
ошибкой: раскрытая ветка показывает failure placeholder, повторное раскрытие
позволяет повторить загрузку, ожидающего worker больше нет.
Collapse отменяет ожидающие запросы поддерева. Удаление host инвалидирует все
ответы и вызывает cooperative cancellation; если источник в этот момент
заимствован приложением, cancellation best effort, а поздний ответ всё равно
не может быть установлен в удалённый host.

## Пример и доступность

`cargo run --release -p xaml-form -- --tree` открывает общий источник в TreeView
и TreeGrid. Команды загрузки позволяют явно принять либо отменить отложенный
ответ; сеть для примера не требуется. Перенос узлов изменяет источник в памяти.
Закреплённые колонки читаются в визуальном порядке слева направо.

## Прокрутка, доступность и границы

Модель хранит разреженные интервалы раскрытых веток. Миллион индексированных
строк не создаёт миллион retained widgets. Scroll рассчитывается в f64,
финальная локальная геометрия — в f32. Fixed row height=28, header=32,
overscan=2; кадр с более чем 4096 материализованными строками явно отклоняется.
Явный большой Shift-range хранит выбранные ключи и может посетить весь диапазон;
это не работа каждого кадра. Structural refresh сохраняет верхний ключ и
смещение внутри строки, либо ближайшего видимого предка, либо прежний индекс
при удалении ключа.

`GridFrame::semantics` содержит видимые строки и ячейки, parent, level,
position/set size, selected/focused/expanded/busy. Пример XAML проецирует их в
AccessKit TreeItem либо Row/Cell, предоставляет Focus/Click/Expand/Collapse и
scroll, проверяет stale и disabled действия. NodeId выделяется отдельно от
RowKey; скрытые элементы удаляются из bounded map. Проверки Rust и проекции
UIA не заменяют отдельные оконные проверки и испытание экранным диктором.
