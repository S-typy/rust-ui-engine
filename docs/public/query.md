# Типизированные запросы

`rust-desktop-ui-data` предоставляет `QueryEngine` для фильтрации, сортировки,
группировки, выражений и итогов над проверенным `DataTable`. Движок не зависит
от UI. Запрос описывается Rust-структурами; строкового языка скриптов, SQL,
произвольных функций и обращения к свойствам приложения нет.

```rust
use rust_desktop_ui_data::{
    Aggregate, AggregateFunction, CellValue, ComparisonOperator, Criteria,
    DataError, DataTable, QueryEngine, QueryExpression, QueryRequest, QueryResult,
};

fn summarize(table: &DataTable) -> Result<QueryResult, DataError> {
    QueryEngine::execute(table, &QueryRequest {
        filter: Some(Criteria::Compare {
            left: QueryExpression::field("Quantity"),
            operator: ComparisonOperator::GreaterOrEqual,
            right: QueryExpression::literal(CellValue::Integer(10)),
        }),
        group_by: vec![QueryExpression::field("Category")],
        aggregates: vec![
            Aggregate {
                function: AggregateFunction::CountRows,
                expression: None,
            },
            Aggregate {
                function: AggregateFunction::Sum,
                expression: Some(QueryExpression::field("Quantity")),
            },
        ],
        ..Default::default()
    })
}
```

`QueryRequest` содержит необязательный `filter`, списки `order_by`, `group_by`
и `aggregates`. Поля должны существовать в схеме и обозначаются точным именем.
`QueryEngine::compile(schema, request)` проверяет весь запрос, включая ветви,
которые могут не вычисляться, и возвращает `CompiledQuery`. Его можно повторно
выполнять на снимках с той же схемой. Изменение схемы требует новой компиляции.
Пустая таблица также проходит проверку запроса.

`QueryResult.row_keys` содержит устойчивые ключи выбранных строк; исходные
значения доступны в таблице. `aggregates` содержит общие итоги в порядке
запрошенных функций. `groups` содержит ключи групп, ключи строк каждой группы
и её итоги. Без `group_by` список групп пуст; пустой результат не создаёт
фиктивную группу. Группировка не меняет общий список строк и общие итоги.

## Типы и выражения

`QueryExpression::Field` и `Literal` задают поле или типизированное значение.
Неявных преобразований между `Integer`, `Real`, `Decimal`, текстом и другими
типами нет. Литерал `Null` совместим с любым типом, но не задаёт числовой тип
сам по себе. `expression_type` возвращает `ExpressionType { kind, nullable }`.
`evaluate_expression(table, key, expression)` вычисляет отдельное выражение;
неизвестный ключ возвращает `UnknownRow`.

| Выражение | Семантика |
|---|---|
| `Arithmetic` | `Add`, `Subtract`, `Multiply`, `Divide` для одинаковых числовых типов |
| `Lowercase` | Unicode lowercase текста, без locale-зависимой collation |
| `TextLength` | Количество Unicode scalar values, не байтов и не графем |
| `Coalesce` | Первое значение, отличное от null; правая ветвь вычисляется при необходимости |

Арифметика распространяет null. Целые операции проверяют переполнение;
целое деление отбрасывает дробную часть к нулю. Деление на ноль и бесконечный
результат `Real` возвращают ошибку. NaN и infinity запрещены также в литералах.
`Decimal` поддерживает сложение, вычитание и умножение с точными коэффициентами;
деление decimal отклоняется при компиляции. Переполнение коэффициента,
промежуточного приведения масштаба или превышение 28 дробных разрядов — ошибка,
без скрытого перехода к `f64` и без округления выражений.

## Критерии и null

`Compare` поддерживает Equal, NotEqual, Less, LessOrEqual, Greater и
GreaterOrEqual для одинаковых типов. `IsNull` проверяет именно null.
`TextMatch` содержит Contains, StartsWith и EndsWith, с режимом Ordinal или
UnicodeLowercase. Символы `%`, `_`, кавычки и SQL-подобный текст имеют обычный
буквальный смысл. Это не регулярные выражения или SQL LIKE.

Результат критериев — `TruthValue::{True, False, Unknown}`. Любое сравнение
с null, включая `Null == Null` и `Null != value`, даёт Unknown. TextMatch с
null также даёт Unknown. Фильтр сохраняет только True. Для проверки null
используется IsNull; пустая строка, пустой Binary и null различаются.

`All` использует логическое AND, `Any` — OR, `Not` — отрицание.
False AND Unknown = False, True AND Unknown = Unknown;
True OR Unknown = True, False OR Unknown = Unknown; NOT Unknown = Unknown.
Пустой All равен True, пустой Any — False. Вычисление идёт слева направо
с коротким замыканием. Все ветви предварительно проходят проверку типов.
`evaluate_criteria` возвращает трёхзначный результат без фильтрации таблицы.

## Порядок и группировка

`QueryOrder` задаёт выражение и `SortDirection`. Сравнение типизированное:
null первым по возрастанию и последним по убыванию; bool — false перед true;
числа — численно; дата и время — хронологически; текст — по порядку Rust strings;
Binary — лексикографически по беззнаковым байтам. Real -0 и +0 равны.

При равенстве всех выражений используется ключ строки по возрастанию,
независимо от направлений сортировки. Без `order_by` также используются ключи
по возрастанию. Поэтому одинаковые снимки с разным физическим порядком строк
дают одинаковый результат. Старый `DataQuery` сохраняет свой контракт:
без сортировки он оставляет исходный порядок снимка.

Группы сортируются лексикографически по выражениям ключа, по возрастанию,
с null первым. Null одной позиции принадлежит общей null-группе.
Строки внутри группы сохраняют порядок общего результата. Вычисление критериев
и накопление итогов используют возрастающий ключ строки, чтобы выбор ошибки
и результат Real-накопления не зависели от порядка хранения.

## Итоги

| AggregateFunction | Результат |
|---|---|
| CountRows | Integer, число выбранных строк, `expression=None` |
| CountValues | Integer, число ненулевых значений выражения |
| Sum | Сумма Integer/Real/Decimal того же типа |
| Minimum / Maximum | Минимальное / максимальное ненулевое значение любого типа |
| Average | Decimal для Integer/Decimal; Real для Real |

У всех функций кроме CountRows требуется выражение. Null исключается из
накопления и знаменателя Average. Пустой набор и набор только из null дают
CountValues = 0; Sum, Minimum, Maximum и Average возвращают null.
CountRows пустого набора равен 0. Общие итоги считаются после фильтра.

Integer Sum проверяет диапазон `i64`. Integer Average накапливается в `i128`
и не теряет точность при преобразовании больших целых. Decimal Average делит
точный коэффициент на число значений, сохраняет до 28 дробных разрядов и
округляет последнюю цифру от нуля при половине. Повторяющаяся дробь `1/3`
становится `0.3333333333333333333333333333`. Переполнение коэффициента или
промежуточного накопления возвращает ошибку. Real-накопление выполняется
в фиксированном порядке и требует конечного результата на каждом шаге.

## Источники и провайдеры

`DataSource::evaluate_query(&request)` выполняется над полным принятым снимком.
Текущие `DataQuery`, видимые строки, revision и редактор не меняются;
I/O не выполняется. Для новых данных сначала вызывается явный refresh или
synchronize. Ошибка вычисления возвращается вызывающему коду и не изменяет
`DataSource::last_error`, поскольку это операция чтения.

`QueryEngine::execute_provider(&mut adapter, request)` — отдельная явная операция
чтения. Встроенные CollectionAdapter и SqliteAdapter объявляют
`QueryCapabilities::local_only()`: загружают полный проверенный снимок
и применяют одинаковый локальный движок. SQLite collation/affinity не меняет
семантику запросов, и пользовательские критерии не превращаются в SQL.

Провайдер может объявить `QueryCapabilities`: точную `semantics_version`
и поддержку filtering, expressions, ordering, grouping, aggregates. Флаг
означает поддержку всех типов и операторов категории, включая ошибки,
лимиты и стабильный порядок. `CompiledQuery::required_capabilities()` показывает
потребности запроса; `execution(capabilities)` выбирает Local или Pushdown.
Даже запрос без явного order_by требует ordering для устойчивого порядка ключей.

Pushdown вызывается только при совпадении `QUERY_SEMANTICS_VERSION`, наличии
`DataAdapter::query_schema()` и покрытии всех требуемых категорий. Перед вызовом
`query_pushdown` запрос проверяется по объявленной схеме. Провайдер обязан
исполнить весь запрос на согласованном снимке и обнаружить изменение схемы.
Если версия, metadata или возможности не подходят, загружается полный снимок
и запрос целиком вычисляется локально. Частичный pushdown не применяется;
ошибка уже выбранного pushdown возвращается без повторного скрытого чтения.
Capability — контракт реализации провайдера, а не проверка стороннего SQL-кода.

## Границы и проверки

| Граница | Максимум |
|---|---:|
| Узлы AST, включая aggregates | 512 |
| Глубина дерева | 32 |
| Термы каждого order_by/group_by/aggregates | 128 |
| Общий payload литералов и имён полей | 1 МиБ |
| Расчётный объём рабочего состояния и результата | `DataLimits.max_bytes` таблицы |

Объём учитывает сохранённые выражения сортировки/группировки, ключи и итоги;
он не является измерением allocator overhead. Локальная обработка синхронная
и применяет `max_text_bytes`/`max_binary_bytes` конкретной таблицы также к
вычисляемым значениям и промежуточным lowercase-строкам. Расширение Unicode
при lowercase может превысить лимит и вернуть Capacity. Это действует и для
отдельных `evaluate_expression`/`evaluate_criteria`.
Обработка ограничена снимком. Парсер текстовых выражений, joins, оконные функции,
постраничное SQL-выполнение и CRUD-пакеты в этот API не входят.

Unit-проверки охватывают все типы и направления сортировки, null-логику,
пустые наборы, точную decimal-арифметику/средние, переполнение, ограничения AST,
неизменность источника и выбор provider/local execution. SQLite feature
добавляет прямую проверку одинаковых критериев, порядка, групп и итогов
на коллекции и SQLite, включая collation и SQL-подобный текст в фильтре.
