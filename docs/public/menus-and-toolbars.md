# Командные поверхности и подсказки

Кнопки, меню и панели используют один `CommandRegistry`. Перенос команды в
overflow не создаёт копии её checked state или обработчика. `activate` проверяет
доступность непосредственно перед выполнением; раскрытие меню не выполняет
основную команду SplitButton.

## Кнопки и содержимое

`set_button_chrome(id, ButtonChrome::Link)` включает акцентную подпись,
подчёркивание и роль Link. Команда приложения определяет действие; библиотека
сама не открывает URL. Focus, pointer release outside, Enter и Space используют
обычный lifecycle Button.

`set_repeat_button(id, Some(RepeatButtonSettings { delay, interval }))` задаёт
повторение для обычной Button. Допустимы задержка 1–60000 мс и интервал
16–60000 мс; значения по умолчанию — 400 и 80 мс. Host включает
`repeat_deadline()` в свой ближайший таймер и вызывает `repeat_tick(now)`.
Один tick выполняет максимум одну активацию; пропущенные интервалы не
воспроизводятся пачкой. После первого повтора release не добавляет действие.
При коротком нажатии остаётся обычная активация на release. Enter и semantic
activation всегда однократны; blur, потеря capture и отключение прекращают
повторение. Меню и flyout не могут одновременно иметь repeat policy.

`set_button_content(id, Some(root))` устанавливает готовое retained-поддерево
для Button, ToggleButton, CheckBox, RadioButton или открытого MenuItem.
Допустимы до 1024 неинтерактивных узлов: панели, подписи, значки, изображения.
Дочерние узлы не перехватывают pointer и не входят в Tab-порядок. Команда,
semantic label и индикатор принадлежат исходной кнопке. Собственное содержимое
заменяет только стандартную подпись и icon. Замена или `None` отсоединяет
прежний root без уничтожения WidgetId. Удаление владельца удаляет прикреплённое
содержимое. Изменения дерева проверяются также при `update`; интерактивный
контрол в шаблоне возвращает ошибку.

## Retained Popup / Flyout

`flyout(anchor, Size)` возвращает `Flyout { container, content }`. Содержимое
создаётся обычными builders внутри `content`, в том числе редакторы, layout и
вложенные кнопки. Закрытие скрывает subtree, сохраняя документы, selection,
undo и идентификаторы. `open_flyout` требует доступного, видимого и уже
размещённого anchor; `close_flyout` закрывает также вложенные поверхности.

`set_flyout_placement` задаёт желаемый размер 1–16384 logical pixels и
`FlyoutPlacement::Below` либо `Beside`. Размещение выбирает доступную сторону
и ограничивается viewport. Большое содержимое должно использовать ScrollViewer.
Лимиты — 256 retained flyouts и восемь одновременно вложенных поверхностей.

`set_button_flyout` связывает flyout с его некомандной Button. Это также
подходит для `SplitButton.dropdown`: primary action остаётся независимым.
`split_button_content(parent, label, command, style)` создаёт такой SplitButton
без пунктов меню; flyout создаётся с anchor `split.dropdown` и присоединяется
через `set_button_flyout`. Обычный `split_button` принимает непустое меню.
`set_flyout_anchor` меняет владельца после разрешения named targets формы,
предварительно закрывая старую цепочку и убирая старую button association.

Escape закрывает верхнюю поверхность и возвращает доступный focus; внешний
pointer down закрывает затронутую цепочку. Tab циклически проходит по её
содержимому. Blur, скрытие, отключение или удаление anchor закрывают overlay.
Удаление anchor уничтожает принадлежащее ему retained-содержимое. Меню внутри
flyout используют тот же viewport и завершаются вместе с владельцем.

## MenuBar и изменение открытого меню

`menu_bar(parent, &[MenuBarItem], style)` создаёт горизонтальную полосу из
1–32 меню. Left/Right переходят между доступными заголовками; Up/Down/Enter
раскрывают меню. При открытой цепочке переход между заголовками открывает
соответствующее меню. Вложенные уровни сохраняют обычную навигацию.

`set_menu_entries(owner, entries)` проверяет новое дерево целиком до изменения
состояния. Открытый уровень перестраивается, его вложенные уровни закрываются,
а focus следует прежней команде, если она осталась доступной. Ошибочные пустые,
слишком глубокие или слишком большие деревья сохраняют открытое меню целиком.
Общие лимиты меню: восемь уровней, 256 элементов и 1 MiB UTF-8 текста.

## ToolBar и BarManager

`tool_bar(parent, key, items, style)` возвращает `ToolBar` с `container`,
`content` и `overflow`. `ToolBarItem` имеет устойчивый key, видимость,
предпочтительную ширину и kind: `Command`, `Separator` либо `Editor(WidgetId)`.
Командная ширина 0 означает измерение подписи. Embedded editor передаётся
как существующее целое поддерево; его обязательные внутренние части нельзя
передавать по отдельности.

При нехватке места постоянные item hosts переносятся в прокручиваемый flyout.
Сохраняются WidgetId, документы редакторов и общая command state. При расширении
окна те же hosts возвращаются в строку. `customize_tool_bar` принимает полный
список текущих keys в новом порядке с видимостью; неизвестные и повторные keys
отклоняются до изменений. Один экземпляр Controls содержит до 32 bars, каждая
до 128 items. Keys состоят из 1–128 ASCII букв, цифр, точек, дефисов и `_`.

`bar_manager` создаёт верхнюю, нижнюю, левую и правую docking lane плюс
`content` приложения. `place_tool_bar` перемещает готовую панель в lane или
`BarPlacement::Floating { x, y, width, height }`. Floating означает поверхность
внутри текущего viewport; API Controls не создаёт отдельное окно ОС. Геометрия
ограничивается окном, редакторы и команды не пересоздаются.

Автоматическая высота MenuBar следует `control_height` текущей плотности,
а ToolBar — `control_height + 8`. При смене плотности контейнеры обновляются
вместе с кнопками, поэтому их границы и рамка фокуса остаются внутри клипа.
Явный `Height`, binding высоты и отличающееся значение, установленное приложением,
сохраняются. Floating использует высоту размещения; возврат в docking lane
восстанавливает прежнюю автоматическую либо явную высоту панели.

`bar_snapshot` / `restore_bars` сохраняют только расположение, keys, порядок и
видимость. `BarSnapshot::to_json/from_json` используют version 1 и лимит 64 KiB;
неизвестные поля, версии, keys, дубликаты и нечисловая геометрия отклоняются.
WidgetId, содержимое редакторов и обработчики в JSON не входят. Автоматического
файлового чтения или записи нет: приложение само выполняет явные команды
сохранения и восстановления.

## RichToolTip

`set_rich_tooltip` принимает `RichToolTip { header, text, icon, image,
image_description }`. Изображение — immutable Bitmap; его смысл описывается
непустым `image_description`. Совокупный semantic текст не превышает 4096 UTF-8
байт, header — 1024. На Controls допускаются 256 rich tips и 16 MiB уникальных
bitmap данных. Ошибка сохраняет прежнюю подсказку; обычный `set_tooltip`
заменяет rich content текстом.

Подсказка появляется после hover delay, не создаёт focusable widgets и не
перехватывает ввод. Заголовок, body и image description доступны в semantic
описании anchor сразу, без ожидания hover. Размер ограничен 320 logical pixels
по ширине и viewport по высоте; длинное содержание визуально обрезается,
полное описание остаётся доступным. Native screen-reader озвучивание зависит
от платформенного host и проверяется отдельно от semantic tree.
