# Разделы и страницы

`NavigationModel` хранит маршруты, разделы, текущую страницу и ограниченную
историю. `Controls::navigation_pane` создаёт постоянные контейнеры страниц.
Содержимое размещается один раз через `navigation_page_host`; переключение
страницы и вида не пересоздаёт её элементы, bindings или редакторы.

## Модель и переходы

`NavigationSection::new(id, label)` и `NavigationPage::new(route, section, label)`
задают явный реестр. Маршрут — непрозрачный идентификатор, а не URL или имя файла.
`NavigationModel::new` проверяет уникальность и ссылки на разделы до монтажа.
Начальная страница должна быть доступна.

- `navigate(owner, route, NavigationMode::Push)` добавляет запись. После Back
  новый Push удаляет прежнюю ветку Forward.
- `NavigationMode::Replace` заменяет текущую запись, сохраняя длину истории.
- `navigation_back` и `navigation_forward` перемещают указатель без новых записей
  и пропускают отключённые маршруты.
- `set_navigation_page_enabled` меняет доступность перехода. Отключение текущего
  маршрута оставляет его страницу видимой до успешного перехода.
- Неизвестный или отключённый целевой маршрут не меняет страницу и историю.

`NavigationValidator` синхронно разрешает или отклоняет переход до публикации.
Один принятый переход с новым маршрутом создаёт один `NavigationChanged`.
Приложение читает `drain_navigation_events`; очередь ограничена 256 событиями
на `Controls`. При заполнении следующий переход отклоняется без изменения
состояния. Повторный переход на текущий доступный маршрут не создаёт события.

Валидатор живёт вместе с навигацией; замена пользовательского валидатора
выполняется через `set_navigation_validator` и не удаляет установленные guards
привязки к source (до 64 guards на экземпляр). Валидатор не выполняет загрузку
страниц. Приложение самостоятельно загружает данные в уже созданные элементы.

Отказ валидатора при клике или клавиатурном переходе сохраняет страницу и историю,
не создаёт событие успешного перехода и отображает причину в доступном заголовке.
`navigation_error` возвращает эту причину; успешный переход или
`clear_navigation_error` очищают её. Программные методы возвращают `Err`.
Текст причины ограничен 512 UTF-8 байт и общими ограничениями текстового движка;
неподходящая причина заменяется сообщением «Переход отклонён».

## Представления

`NavigationSettings.view` и `set_navigation_view` выбирают:

| Вид | Представление |
|---|---|
| `Side` | Боковая панель разделов и страниц |
| `Accordion` | Заголовки разделов с одной раскрытой группой страниц |
| `Hamburger` | Компактная панель значков с кнопкой раскрытия подписей |
| `Office` | Страницы активного раздела и отдельная нижняя панель разделов |
| `Frame` | Только текущая страница и заголовок с необязательной историей |

Все виды используют одну историю и те же `WidgetId`. Переход к странице через
историю или внешнюю привязку выбирает соответствующий раздел. Списки разделов
прокручиваются, длинные подписи сокращаются визуально, полные доступные имена
сохраняются. `pane_width` задаёт 120–640 логических единиц; при узком окне панель
уменьшается, оставляя место содержимому. `show_history=false` скрывает кнопки
истории. Alt+Left / Alt+Right продолжают работать внутри навигации.

## Редактирование и жизненный цикл

Смена страницы через навигацию сохраняет незавершённый draft и последнее
принятое значение. Предварительная IME-композиция отменяется, всплывающие окна
старой страницы закрываются. При возвращении восстанавливается последний
существующий доступный фокусируемый элемент страницы. Если его больше нет,
фокус получает общий контейнер страницы. Внешний фокус не перехватывается.
Обычная смена фокуса вне навигационного перехода по-прежнему следует настройкам
редактора, включая `CommitOnLostFocus`.

Стрелки/Home/End в панели перемещают фокус и прокручивают панель к кнопке,
Enter/Space активируют кнопку.
Alt+Left/Right во время IME сначала отменяют композицию; следующий жест выполняет
переход. Повтор клавиши не создаёт несколько переходов. Текущая страница имеет
семантическое имя, её кнопка — выбранное состояние. Скрытые страницы исключены
из доступного дерева.

Удаление владельца освобождает все страницы и связанные всплывающие окна.
Публичные handles позволяют размещать содержимое в page hosts, но внутренние
контейнеры и кнопки нельзя удалять или переносить. Перед переходом и изменением
настроек проверяется точная структура их родителей.

## Compiled XAML

```xml
<NavigationPane Route="{Binding CurrentRoute}" View="Side"
                PaneWidth="220" HistoryLimit="64" ShowHistory="True">
  <NavigationSection Id="work" Header="Работа" Icon="FolderOpen">
    <NavigationPage Route="home" Header="Главная">
      <StackPanel Spacing="12">
        <TextBlock Text="Документ"/>
        <TextBox x:Name="Draft" Text="{Binding Draft}"/>
      </StackPanel>
    </NavigationPage>
    <NavigationPage Route="settings" Header="Параметры">
      <CheckBox Content="Показывать уведомления"/>
    </NavigationPage>
  </NavigationSection>
</NavigationPane>
```

`Accordion` и `NavigationFrame` — сокращения с соответствующим начальным видом.
`Route` по умолчанию TwoWay/PropertyChanged; публикация внешнего значения
использует Replace. Ошибочное обновление source оставляет текущую страницу;
ошибка начального Route binding отменяет весь монтаж формы. Статический Route
можно опустить: выбирается первая доступная страница.

Страница содержит ровно один визуальный корень; StackPanel/Grid позволяют
разместить несколько элементов. Общие names, resources, styles и bindings
используются внутри содержимого. Метаданные разделов и страниц статические,
не допускают bindings. `NavigationPage.IsEnabled` задаёт начальную доступность;
Rust API изменяет её во время работы.

## Границы

Один экземпляр поддерживает 1–16 разделов, 1–64 страницы и 1–128 записей истории.
До 32 экземпляров на `Controls`. Идентификаторы: 1–128 ASCII символов из букв,
цифр, `/_.-`; подписи: до 128 графем и 512 UTF-8 байт, одна непустая строка.
Общий размер метаданных ограничен 32 KiB. Действуют общие ограничения XAML и
текстового движка. Все страницы монтируются сразу; асинхронное создание,
сериализация истории и адресная строка не входят в этот профиль.

Пример `NavigationWindow.xaml` показывает все виды, историю, внешнее обновление
маршрута, отключение страницы и сохранение draft во вложенных редакторах.
