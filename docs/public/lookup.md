# LookupEdit: выбор записи из справочника

`lookup_edit` создаёт редактор, значение которого ссылается на разрешённую запись
источника. Ключ задаёт идентичность; подпись служит отображению и поиску.
Индекс строки и её положение после фильтрации не являются значением.
Общие привязки источников описаны в [формах](forms.md), множественный выбор —
в [ComboBox](combo-box.md), ограниченные строки — в [ListBox](list-box.md).

## Принятое значение

Одиночный редактор принимает существующий включённый ключ либо пустой выбор.
`set_selected_keys` отклоняет неизвестные и отключённые записи. Ввод произвольного
текста разрешён как черновик поиска, но не создаёт новую запись. Enter и обычное
подтверждение редактора принимают только однозначно найденную подпись.
Если несколько записей имеют одну подпись, требуется выбрать запись из списка.
Уже принятый ключ сохраняется при неизменённой подписи, даже если другие записи
получили такую же подпись. Явное назначение ключа также остаётся однозначным.

Подписи одиночного поля нормализуются по правилам однострочного редактора.
Видимый черновик и принятое значение разделены: ошибка валидации сохраняет
черновик и не публикует новый выбранный ключ. `SelectionValidator` и валидатор
модели проверяют весь кандидат до изменения принятого выбора.

`SelectionMode::Multiple` использует `ComboSelectionSettings`, флажки и
`ComboSelectionPresentation::Tokens` либо `Text`. Поисковый текст не является
значением. `selected_keys` возвращает принятые ключи, `combo_selection_draft` —
черновик; `commit_combo_selection` и `cancel_combo_selection` завершают его явно.
Фильтрация сохраняет выбранные ключи, которых нет среди текущих результатов.
Порядок выбора соответствует переданным ключам и порядку добавления в черновик.

## Поиск по колонкам

`LookupSearchSettings` задаётся через `set_lookup_search_settings`:

| Свойство | Значение |
|---|---|
| `columns` | Уникальные индексы 0..31; пустой список означает все колонки |
| `mode` | `Contains` по умолчанию либо `StartsWith` |
| `comparison` | `UnicodeLowercase` по умолчанию либо `Ordinal` |

Колонка 0 — основная подпись, следующие — `SelectionItem::columns`.
При объявленных заголовках индекс должен находиться в их диапазоне.
Без заголовков отсутствующая ячейка не совпадает с запросом.
Пустой запрос показывает весь источник, включая отключённые записи;
отключённые строки доступны для просмотра, но не для выбора.

`Ordinal` сравнивает точный Unicode-текст. `UnicodeLowercase` применяет
стандартное Unicode-преобразование в нижний регистр к обоим операндам.
Сравнение независимо от культуры отображения: без нормализации, удаления
диакритики, лингвистической сортировки и полного case folding. Например,
`Ё` совпадает с `ё`, но не с `е`; `ß` не заменяется на `ss`.

Изменение политики поиска проверяет новые видимые строки до публикации настроек.
При ошибке сохраняются предыдущая политика, раскрытый список и принятые ключи.
Поиск локальный и синхронный; удалённый запрос, debounce и Grid-представление
в этот API не входят.

## Обновление источника

`set_selection_items` сохраняет выбор по ключам при перестановке и изменении
подписей. Удалённые и отключённые ключи исключаются из принятого выбора и
черновика. Если это изменение не проходит валидатор, источник отклоняется целиком.
Текст принятой подписи, настройки и новые видимые строки проверяются до
публикации. Уже открытый список обновляется на месте: сохраняются допустимый
курсор, поисковый черновик, композиция и WidgetId сохранившихся видимых строк.

Обновление одиночного источника инвалидирует незавершённую асинхронную проверку
старой подписи. Поздний ответ не может выбрать новую запись с той же подписью.
Режим чтения запрещает пользовательский выбор; корректные обновления данных
приложением продолжают работать.

`ControlBindings` сохраняет исходный тип ключа: строка `"1"`, число `1` и
`true` различны. Для `ObservableCollection` учитываются идентичность экземпляра
и ревизия. Замена коллекции тем же путём подключает новый источник; события
отсоединённого экземпляра больше не меняют редактор. Ошибка проекции сохраняет
прежние строки, отображение ключей и принятое значение. Уже сделанная внешняя
запись в модель источника при этом не откатывается: ошибка привязки сообщает,
что представление ещё использует предыдущий принятый источник.

## Compiled XAML

```xml
<LookupEdit ItemsSource="{Binding People}"
            DisplayMemberPath="Name" ValueMemberPath="Id"
            SelectedValues="{Binding SelectedPeople}"
            SelectionMode="Multiple" SelectionPresentation="Tokens"
            SearchColumns="0,1" SearchMode="Contains"
            SearchComparison="UnicodeLowercase">
  <LookupEdit.Columns>
    <LookupColumn Field="Name" Header="Имя" Width="180" />
    <LookupColumn Field="Department" Header="Отдел" Width="160" />
  </LookupEdit.Columns>
</LookupEdit>
```

Для одиночного выбора используется `SelectedValue`. Первая объявленная колонка
соответствует `DisplayMemberPath`. `ItemTemplate` поддерживает общий ограниченный
шаблон строки списка; вложенные редактируемые поля в строках не создаются.

Источник ограничен 100000 записями, 16 МиБ суммарного текста и 32 отображаемыми
колонками. Множественный выбор ограничен 256 ключами. Геометрия, число
материализованных строк и повторное использование строк подчиняются контракту
[виртуализации](virtualization.md). Проверка текстовых графем выполняется при
материализации строки; ошибка недопустимого текста вне видимого диапазона
может обнаружиться позднее при прокрутке или поиске.
