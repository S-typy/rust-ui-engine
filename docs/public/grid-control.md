# GridControl: таблицы данных

`Controls::grid_control` показывает плоский типизированный `DataSource` из
[ui-data](data.md). В основе — виртуализация TreeGrid: retained nodes не создаются
на каждую запись. Кадр содержит строки viewport и overscan, видимые колонки,
закреплённые колонки и семантику. Рисование не обращается к SQLite.

Пример запуска: `cargo run -p xaml-form --release --locked -- --data`.
Слева 5 000 строк коллекции Rust, справа 1 000 строк настоящей SQLite в памяти.
Пример не сохраняет базу при закрытии; для постоянных данных приложение передаёт
существующий файл в `SqliteAdapter::open`.

## XAML

```xml
<GridControl x:Name="OrdersGrid" DataSource="Orders"
             FilterText="{Binding Filter}"
             SelectedValue="{Binding SelectedKey}"
             IsReadOnly="{Binding ReadOnly}">
  <GridControl.Columns>
    <GridColumn FieldName="Code" Header="Код" Width="100" IsPinned="True"/>
    <GridColumn FieldName="Name" Header="Наименование" Width="240"/>
    <GridColumn FieldName="Quantity" Header="Количество" Width="120"/>
  </GridControl.Columns>
</GridControl>
```

До монтажа приложение регистрирует источник:
`ui.register_data_source("Orders", Rc::new(RefCell::new(source)))?`.
Имя ограничено 128 ASCII-символами идентификатора. XAML не содержит SQL,
путь к базе, строку подключения или обработчики. Неизвестный источник/поле
отклоняется до изменения дерева формы.

`GridColumn` можно помещать непосредственно в GridControl либо в
`GridControl.Columns`; смешивать варианты нельзя. Без колонок используются
поля схемы. `FieldName` — точное имя поля, включая пробелы и Unicode,
не property path. До 256 байт UTF-8, без NUL. Поля не повторяются, до 64 колонок.
`Header` по умолчанию равен FieldName, максимум 4096 байт.

Колонки создаются при монтаже. Смена схемы живого источника обновляет данные,
но не перестраивает состав колонок автоматически: удалённое поле отображается
пустым и недоступно для редактирования. Для другого состава полей приложение
создаёт GridControl с соответствующими колонками.

Width/MinWidth/MaxWidth должны быть конечными и удовлетворять
`32 ≤ MinWidth ≤ Width ≤ MaxWidth ≤ 4096`; defaults 140/32/4096.
IsPinned и IsReadOnly по умолчанию False. ReadOnly схемы имеет приоритет.
В XAML Grid таблица занимает доступную ячейку; в StackPanel автоматическая
высота — 320. Явные Width/Height и общие layout-свойства поддерживаются.
VerticalAlignment Top/Center/Bottom сохраняет автоматическую высоту 320.
При привязке Height значение Null/Auto также выбирает высоту 320.

## Выделение, запросы и колонки

- Клик выбирает строку/ячейку. Стрелки перемещают фокус; PageUp/PageDown,
  Home/End переходят по строкам, Left/Right — между колонками.
- Клик по заголовку переключает направление сортировки. Граница заголовка
  изменяет ширину, перетаскивание заголовка меняет порядок колонок.
- Вертикальная и горизонтальная прокрутка, Shift+wheel для горизонтали.
  Закрепление доступно через IsPinned и `pin_grid_column`.
- FilterText — ограниченный 4096 байтами поиск по отображаемым значениям.
  Сортировка типизированная; семантика запросов одинакова для коллекции и SQLite.
- SelectedValue — десятичная **строка i64** либо Null; через f64 ключи не проходят.
  FilterText и SelectedValue имеют defaults TwoWay/PropertyChanged,
  IsReadOnly — OneWay. Стабильные ключи сохраняются при изменении порядка.

`grid_frame`, `grid_source`, `grid_settings`, `grid_selected_key`, `grid_filter`
позволяют получить текущую модель. `grid_scroll_to`, `grid_focus_cell`,
`set_grid_selected_key` и `set_grid_filter` доступны приложению.
Один зарегистрированный источник может использоваться несколькими таблицами;
его query общее для всех таких представлений.
При нескольких начальных literal FilterText одного источника действует
последнее значение в порядке монтажа. Скрытая фильтром выбранная запись
сохраняет SelectedValue; удаление самой записи очищает ключ.
Если у одной таблицы явно заданы начальные FilterText и SelectedValue,
выбранный ключ должен входить в результат этого фильтра: сочетание проверяется
до монтажа без изменения зарегистрированного источника. Без собственного
начального фильтра допускается известный ключ, скрытый общим query источника.

## Редактирование и обновления

F2 или Enter открывает общий TextBox поверх редактируемой ячейки. Enter
подтверждает, Escape отменяет; корректное значение подтверждается при уходе
фокуса. Ошибка сохраняет введённый текст и исходное значение. Схема проверяет
тип/nullability/read-only, SQLite дополнительно проверяет ограничения таблицы.
Неизменённое nullable-текстовое значение остаётся Null. Для исходного текста
с переводами строк открытие однострочного редактора отклоняется; изменение
такого значения доступно через типизированный API источника.

Decimal, Date, Time и Binary сохраняют точные значения при отображении и разборе
ввода. Дата отображается как ДД.ММ.ГГГГ; время сохраняет ненулевые секунды и
дробную часть; Binary использует `0x` и пары hex-цифр. Форматы и ограничения
описаны в [контракте данных](data.md). Однострочный редактор ограничен 1 МиБ
UTF-8 и настроенным MaxLength. Hex-представление больших Binary может превысить
этот предел: открытие редактора отклоняется до изменения выделения, фокуса
и сессии. Значение остаётся доступно через типизированный API источника.
Read-only текущей схемы и отказ валидатора исходного значения также отклоняют
открытие сессии, сохраняя прежний текст редактора и выбранную ячейку.

`begin_grid_edit`, `commit_grid_edit`, `cancel_grid_edit` позволяют управлять
сессией из Rust. При неудачной проверке commit возвращает false; сообщение
доступно через `grid_error` и семантику editor. Нельзя молча отбросить активный
черновик сменой фильтра/выделения или обновлением кадра. Изменения внешнего
источника откладываются для этой таблицы до завершения сессии; запись сравнивает
исходное значение ячейки с актуальным и отклоняет конфликт.

Наблюдаемая Rust-коллекция принимается автоматически при update через
`DataSource::synchronize`; при неизменной версии повторного чтения нет.
Изменения сохраняют выделение по ключу и положение верхней видимой записи
при неизменном query. См. [наблюдаемые коллекции](observable-collections.md).

`DataSource::refresh` — явная синхронная операция приложения, необходимая
для внешних изменений SQLite. При ошибке
сохраняется последняя корректная таблица. Кнопка «Обновить» примера проверяет,
что редактирование закончено, и повторно читает оба источника.

## Доступность и границы

Пример проецирует Grid, количество строк/колонок и виртуальные Row/Cell в
AccessKit. Доступны выделение, фокус, readonly и ошибки; текстовый редактор
сохраняет собственную семантику. Проверка проекции в тестах не означает
проверку настоящим экранным диктором.

Windows-адаптер `accesskit_windows` версии 0.35.1 предоставляет для DataGrid
`SelectionPattern`, но не `GridPattern` и `GridItemPattern`. Row/Cell и их индексы
есть в дереве AccessKit, однако получение ячейки по координатам через эти
UI Automation patterns пока недоступно.

Текущий источник — ограниченный синхронный снимок. Серверная пагинация,
async/cancellation, группировка/итоги, banded headers, произвольные cell templates,
Excel export и встроенный CRUD toolbar таблицы не реализованы этим профилем.
В примере кнопки добавления/удаления принадлежат приложению и меняют коллекцию.
