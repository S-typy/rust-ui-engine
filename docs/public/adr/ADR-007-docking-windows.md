# ADR-007 Докинг и отдельные нативные окна

Статус: принято. Дата: 2026-10-15.

## Контекст

Рабочая область с Ribbon должна размещать документы и инструментальные панели
во вкладках, разделять пространство и открывать панели в отдельных окнах ОС.
Перенос не должен создавать редактор заново или превращать плавающее окно
в прямоугольник поверх того же клиентского пространства.

## Решение

Модель `DockLayout` находится в controls и хранит только расположение:
стабильные идентификаторы панелей, вкладки, бинарные разделения, отдельные окна
и закрытые панели. Мутации атомарны и ограничены по размеру и глубине.
Содержимое, команды и документы принадлежат приложению. В примере каждой панели
соответствует один постоянный `Form`, независимо от её текущего окна и видимости.

`DockView` создаёт retained chrome одной рабочей области и возвращает запросы
к общей модели. Сцена активной панели смещается и отсекается через
`Scene::append_view`; исходные текстовые и скруглённые геометрии сохраняются.
Переход между расположениями не требует переноса WidgetId между независимыми
аренами. Compiled XAML описывает исходный workspace, split, group и pane;
дальнейшие перемещения относятся к runtime.

Platform получает новый `DesktopApplication` и `run_multi`. `WindowKey`
независим от нативного дескриптора. Приложение сообщает желаемый набор окон и
предоставляет `DesktopApp` для каждого из них. Каждое окно имеет настоящую
GPU-поверхность, собственные ввод, DPI, IME, таймеры и AccessKit adapter.
Clipboard общий, ответы сохраняют принадлежность запросившему окну.
Существующий single-window `run` остаётся совместимым.

На Windows отдельные окна имеют native owner, стандартную рамку и сохраняют
системные перемещение, resize и закрытие. Главное окно может использовать
шапку Ribbon по ADR-006. Начальная позиция задаётся приложением; после создания
host сообщает фактическую геометрию, не навязывая исходную позицию повторно.
Изменение владельца требует нового ключа, отсутствующие owner и циклы запрещены.

Удаление окна выполняется в два этапа. Приложение убирает ключ из желаемого
набора, сохраняя представление. Host завершает ввод в порядке focus loss,
IME cancel, pointer leave, уничтожает окно и вызывает `window_closed`.
Связанное состояние панели остаётся у приложения. Демонстрация возвращает панели
в главное окно при закрытии плавающего HWND; закрытие самой панели оставляет
её содержимое для восстановления. Главное окно закрывает всё приложение.

Типизированный `DockSnapshot` версии 1 содержит только расположение и геометрию.
Он не сериализует документы, controls, native handles или GPU-ресурсы.
Controls предоставляет строгий JSON codec snapshot версии 1 с лимитом 1 MiB;
файловый I/O и политика хранения остаются уровнем приложения. Демонстрация
сохраняет и восстанавливает файл только по явной команде.

Для межоконного drag DockView отдаёт неизменяемую проекцию drop targets,
а приложение координирует preview и одну мутацию при отпускании. Source HWND
удерживает capture; Windows host сообщает physical screen position события
и реально верхнее клиентское окно. Преобразование в target client использует
его собственный DPI. Capture-loss отменяет жест без synthetic PointerUp.

Явное восстановление native bounds использует WindowSpec.placement_revision.
Host применяет геометрию один раз и подтверждает revision перед geometry
callback; обычное перемещение окна не увеличивает revision. Старые callbacks
не могут затереть восстановленную модель. При смене snapshot приложение
инвалидирует предыдущие hit regions и отменяет старые жесты без rollback.

## Последствия

Core и controls сохраняют независимость от winit и GPU. Отдельные окна
используют самостоятельные renderer/device, что упрощает первый контракт, но
увеличивает расход GPU-ресурсов. Максимум — главное окно и 16 плавающих.
Координаты событий переводятся в систему соответствующей панели, деревья
accessibility объединяются с постоянными NodeId и отсечёнными physical bounds.

В исходном профиле auto-hide, MDI и общий GPU-device были отложены.
Развитие auto-hide описано ниже; MDI и общий GPU-device остаются за пределами профиля.
Native hit context для межоконного drag пока реализован только на Windows.
Floating position сохраняется логически при DPI окна; точное физическое
восстановление после смены DPI или набора мониторов не гарантируется.
Нативные drag, focus/IME transitions, keyboard и screen-reader сценарии требуют
самостоятельной проверки: unit-тесты маршрутизации и оконные снимки её не заменяют.
Первичная runtime-проверка ограничена Windows; остальные платформы сохраняют
переносимую архитектуру без утверждения об их проверенной docking-интеграции.

## Развитие 2026-10-17: auto-hide

Настройки auto-hide отделены от исходного дерева. Панель остаётся в своей
группе, сохраняя идентификаторы, порядок и долю split; `arrange` фильтрует
только видимое представление. Закрепление возвращает исходное место без
эвристики поиска прежней группы. Перенос панели по-прежнему меняет дерево.

Снимок версии2 добавляет metadata `{ pane, edge, extent }`; версия1 без metadata
мигрирует при чтении. Раскрытая панель — временное состояние одного окна,
не часть сохранённого файла. Ввод и сцена учитывают перекрытие, а постоянный
Form сохраняет документ и bindings. Файловые операции остаются явными командами.

Продуктовый контракт: [Docking](../docking.md).
