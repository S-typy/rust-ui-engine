# ADR-005 Компиляция собственного профиля XAML

Статус: принято для первого профиля форм. Дата: 2026-10-10.
Дополняет [ADR-004](ADR-004-text-controls-platform-treegrid.md).

## Контекст

Приложениям нужен декларативный способ задавать форму и начальные свойства
компонентов. Существующие retained tree, layout, text, controls и GPU renderer
уже определяют поведение и отображение интерфейса. Разметка должна пользоваться
этой архитектурой и выдавать понятную ошибку для неподдерживаемых конструкций.

## Решение

Добавлен независимый `rust-desktop-ui-xaml`. Первый профиль содержит `Window`
с одним `TextBox` в пространстве имён `urn:rust-ui-engine:ui`. Из стандартного
языкового пространства имён XAML используется только `x:Name`. Поддерживаемые
свойства и их ограничения перечислены в [описании профиля](../xaml.md).

`build.rs` вызывает `compile_file`, который разбирает XML через `roxmltree`,
проверяет профиль и генерирует `window_definition() -> WindowDefinition`.
Приложение подключает результат из `OUT_DIR` через `include!`. Возвращаемая
структура хранит типизированные начальные значения; генератор не вставляет
исполняемые выражения из разметки. Диагностика сохраняет путь, строку и столбец.

Компилятор не зависит от controls, winit или wgpu. Адаптер определения к окну
пока находится в `examples/xaml-form`: `Window` задаёт свойства нативного host
и отступы корня, `TextBox` создаётся через `Controls::edit_box`. Изменяемый текст
остаётся в `TextDocument`, а `x:Name` разрешается адаптером в `WidgetId`.
Темы `Light`/`Dark` выбирают собственные `FluentLight`/`FluentDark` controls.

Граница Scene сохраняется: оформление передаётся renderer как независимые
примитивы. Ввод, clipboard, IME и accessibility проходят через существующие
controls и platform host. Разметка не определяет отдельный event loop или
текстовый движок.

## Последствия

Изменение XAML требует новой сборки. Неизвестная конструкция останавливает её;
пропуск неподдерживаемых свойств не допускается. Источник ограничен 1 MiB и
128 XML-узлами, DTD и processing instructions запрещены. Приложению не нужен
runtime-загрузчик XML для запуска формы.

Профиль не реализует bindings, ресурсы, стили, шаблоны, markup extensions,
динамическую загрузку, hot reload или дизайнер. Совместимость с произвольной
WPF/DevExpress-разметкой не заявляется. Общий монтаж произвольного дерева будет
отдельным изменением после появления нескольких типов контейнеров и controls;
двухэлементный адаптер сейчас остаётся примером приложения.

Unit-тесты проверяют namespace resolution, отказы неподдерживаемой разметки,
размеры, диагностику и escaping. Пример компилирует реальный XAML при сборке;
его тесты сравнивают результат с parser и проверяют монтаж, ввод, resize и
семантические действия. Реальные IME/screen reader и визуальный результат GPU
требуют отдельных платформенных проверок.

## Рассмотренные варианты

Загрузка XML при каждом запуске потребовала бы runtime-диагностики ошибок формы
и управления файлами разметки при поставке. Компиляция при сборке позволяет
проверять профиль до запуска и включать начальные значения непосредственно
в приложение.

Переход на WPF потребовал бы .NET/Windows UI backend и изменил бы выбранную
кроссплатформенную архитектуру. Полная реализация WPF XAML включала бы систему
типов, dependency properties, bindings и templates существенно шире первого
примера. Поэтому принят собственный явно ограниченный профиль с общим
языковым ориентиром MS-XAML-2012.

## Лицензирование

Код реализации и оформление собственные, Apache-2.0. Код и ресурсы WPF или
DevExpress не включены. XML parser `roxmltree 0.21.1` имеет лицензию
[MIT OR Apache-2.0](https://docs.rs/crate/roxmltree/0.21.1/source/Cargo.toml.orig).

MS-XAML-2012 опубликована с разрешениями на использование документации для
реализации и перечислена среди спецификаций OSP. Эти условия имеют собственные
границы и не являются гарантией патентной чистоты продукта или покрытием
собственных расширений. Применимые ссылки и ограничения приведены в
[описании лицензирования профиля](../xaml.md#происхождение-и-лицензии).
