# ADR-006 Заголовок Ribbon внутри нативной рамки

Статус: принято. Дата: 2026-10-15.

## Контекст

Отдельные системный заголовок и строка быстрых команд занимают лишнюю высоту.
Для Ribbon требуется общая шапка, сохраняя системные кнопки окна, изменение
размера, оконное меню и независимость controls от платформы.

## Решение

`DesktopApp::title_bar` запрашивает расширение клиентской области в заголовок.
Windows host сохраняет нативный decoration style и использует DWM/Win32 через
`windows-sys`. Он отвечает за рамку, системные действия кнопок и non-client hit testing.
Приложение получает фактическую геометрию кнопок через `WindowChrome` перед
layout и передаёт только свободные прямоугольники для перетаскивания. На других
платформах сохраняется обычный заголовок.

Непрозрачная GPU-поверхность перекрывает DWM-отрисовку caption glyphs в
расширенной клиентской области. Поэтому host добавляет собственные векторные
значки и состояния кнопок поверх копии Scene. Геометрия и обработка системных
действий остаются нативными; декоративные примитивы не добавляют вторые кнопки
в controls и accessibility tree. Исходная Scene приложения не изменяется.

`RibbonHeader` в controls рисует название и QAT, резервируя место справа.
`header_regions` возвращает независимые от платформы логические координаты.
Команды, меню, KeyTips и доступные имена продолжают использовать существующие
controls. Приложение исключает QAT из областей перетаскивания; при открытом
меню отключает перетаскивание шапки, чтобы сохранить закрытие меню кликом снаружи.

Собственный compiled XAML получает `Window TitleBar="Native|Ribbon"`.
Режим Ribbon требует нулевых отступов Window и первого Ribbon у верхнего края.
Корнем может быть Ribbon либо вертикальная StackPanel без собственных
отступов и фиксированного размера. Разметка и ручной AST проходят одинаковую
проверку размещения. Пример включает этот режим и оставляет
`--native-title-bar` для стандартного оформления.

Расширение для строки состояния: допускается корневой Grid без Padding/Spacing,
с единственной колонкой `*` и первой строкой Auto. Ribbon — первый ребёнок
в ячейке (0,0) без spans; все другие прямые дети находятся ниже и не создают
дополнительных колонок. Схема `Auto,*,Auto` оставляет строку состояния у нижнего
края при изменении высоты Ribbon. Платформенная граница и hit testing не меняются.

## Последствия

В controls и компилятор не попадают HWND, DWM и winit. Новые native FFI
локализованы в platform host. Нативные кнопки не дублируются в retained tree.
Изменение ширины, темы и минимизации Ribbon сохраняет документ редактора.

Интеграция Windows остаётся opt-in; Linux/macOS продолжают использовать
существующее оформление. Системные Mica/Acrylic, редактирование QAT и Backstage
не входят в этот контракт. Запросы hit testing и снимки проверяются отдельно
от настоящего перетаскивания, Snap, клавиатурного оконного меню и screen reader.

Системный механизм описан в
[Microsoft: Custom Window Frame Using DWM](https://learn.microsoft.com/en-us/windows/win32/dwm/customframe).
Реализация и оформление принадлежат проекту.
