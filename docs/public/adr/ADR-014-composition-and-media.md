# ADR-014: составные документы и медиа-источники

Статус: принято. Дата: 2026-10-20.

Report Designer и Dashboard объединяют существующие модели и элементы. Они
не должны создавать независимые движки запросов, таблиц, графики или печати.
Медиа-источники требуют отдельной границы, поскольку COM, декодеры и устройства
имеют платформенный lifecycle и могут блокировать вызывающий поток.

Решение:

- `ui-controls` владеет definition/session/view дизайнера и Dashboard. Отчёт
  вычисляет ReportEngine, фильтрацию и итоги — QueryEngine, данные отображают
  существующие GridControl/Chart. Сериализация строгая и версионная.
- Редактирование публикует целый проверенный кандидат. Revision защищает
  отложенные результаты от перезаписи более новых изменений. Вычисление модели
  синхронное, файловый I/O принадлежит приложению.
- Минимальные типы `MediaProvider`, `MediaInfo`, `MediaFrame` находятся в
  `ui-core` без платформенных зависимостей. `MediaSession` в controls управляет
  временем, поколениями запросов и ограниченным mailbox.
- `ui-platform-winit` предоставляет Windows file provider. Он создаётся внутри
  worker, поэтому COM interfaces не переносятся между потоками. Controls не
  импортирует winit, windows или Media Foundation.
- Видео представляется Bitmap в Scene. Аудиовывод, camera device backend,
  аппаратное декодирование и zero-copy остаются отдельными расширениями.
- Приложение владеет playlist, явными file dialogs, сохранением и export.
  Запуск примера не активирует камеру, аудио или печать.

Последствия: общий renderer сохраняет GPU-контракт, а декодирование работает
независимо от UI-потока. Кооперативная отмена не может прервать зависший системный
вызов; ограничение числа worker предотвращает накопление запросов, но для
жёстких сроков отмены требуется изоляция процесса.
