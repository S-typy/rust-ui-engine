# ADR-001: retained tree и независимое ядро

Дата: 2026-10-09. Статус: принято; retained tree и независимый runtime реализованы в M1.

## Контекст

Компонентам с выбором строк, focus, редактированием и доступностью нужна устойчивая
идентичность между событиями. Индекс видимой строки или адрес временного Rust
объекта не подходит для идентичности виджета. При виртуализации элементы
появляются и исчезают независимо от срока жизни данных приложения.

M0 содержал три работающих пакета: `rust-desktop-ui-core`,
`rust-desktop-ui-render-wgpu` и пример `gpu-shell`. Сцена прямоугольников проверяет
границу между моделью и renderer. M1 добавляет дерево/runtime в core и отдельный
действующий пакет `rust-desktop-ui-layout`; Ribbon и TreeGrid не реализованы.

## Решение

Ядро содержит retained runtime с собственной arena и opaque `WidgetId`,
состоящим из identity дерева, индекса слота и поколения. Идентификатор стабилен до удаления узла.
Повторное использование слота меняет поколение; обращение по устаревшему ID
возвращает отсутствие узла. ID другого дерева также не разрешается. При
переполнении поколения слот выводится из повторного использования. Identity
дерева не циклическая; теоретическое исчерпание process-wide u64 identities
завершает создание с panic, вместо выдачи повторной identity.

`UiTree` имеет постоянный root. Insert/remove/reparent поддерживают двустороннее
parent/children соответствие, запрещают циклы и удаление/перенос root. Удаление
subtree инвалидирует все входящие ID. Структурные поля не предоставляются через
mutable references; свойства меняются валидируемыми методами с invalidation.

Логическое дерево хранит структуру и семантическую идентичность. Вычисленные
layout, clips и paint-данные отделены от логической структуры. GPU resources
остаются в renderer. Ключ строки источника данных и `WidgetId` — разные сущности:
будущая виртуализация должна ограничивать число визуальных узлов viewport.
Диапазон 100 000 строк старого rectangle example не является retained tree.

В примере состоянием владеет поток event loop. Callback получает снимок события
и `EventContext`, а не mutable tree. Изменения во время маршрутизации событий
ставятся в очередь `Mutation` и применяются после завершения маршрута.
Цикл M1: нормализация события → hit test → capture/target/bubble →
изменение состояния → dirty flags → layout/scene → запрос перерисовки.
Measure, layout, paint и semantics получают раздельную invalidation.

Focus, hover и pointer capture хранят ID, а не ссылки на узлы. Удаление очищает
соответствующие handlers и interaction state. Layout invalidation пока вызывает
полный layout pass; paint-only и hover/focus не вызывают layout. Paint pass
перестраивает Scene, а idle update повторно использует её без вычислений.
Semantics invalidation ещё не означает реализации accessibility adapter.

`ui-core` и будущие controls не зависят от `winit` или `wgpu`. Core не имеет
внешних dependencies и сохраняет `Rect`, `Color`, `SolidRect`, `Scene`, а также
собственные `LayoutStyle`, `LayoutEngine` и `LayoutSnapshot`. Адаптер
`ui-layout` использует Taffy без внешних типов в API core. Отдельный `ui-graphics`
понадобится при появлении самостоятельной графической подсистемы. Новые crates
выделяются по реальным границам ответственности. Демонстрационная логика
принадлежит примеру `gpu-shell`.

## Альтернативы

- Только immediate-mode интерфейс: потребует отдельной устойчивой модели focus,
  selection и accessibility, поэтому не выбран основой runtime.
- Сырые индексы без поколения: старый ID может незаметно обратиться к другому
  узлу после переиспользования слота.
- Граф взаимных `&mut` или shared pointers: усложняет владение, удаление и
  контролируемые обновления без необходимости для начального runtime.
- Полный набор будущих crates сразу: фиксирует границы до появления реализации.

## Проверка и оставшиеся границы

Unit tests покрывают создание, удаление и переиспользование узлов; чужие и
устаревшие IDs; retirement слота при переполнении поколения; parent/child
invariants; циклы; порядок маршрутизации; queued mutations; очистку focus/capture
и dirty flags. Геометрические тесты adapter проверяют Stack/Overlay/Flex,
constraints, resize и ошибки. Фактическое выполнение проверок фиксируется в
[отчёте M1](../M1_TEST_REPORT.md), а не предполагается из наличия тестов.

Текст, IME, готовые controls, платформенная доступность и виртуализированные
таблицы остаются отдельными этапами. Контракт runtime и ограниченная стратегия
пересчёта описаны в [ADR-003](ADR-003-retained-runtime.md) и
[руководстве API](../retained-ui.md). Граница GPU-сцены сохраняется согласно
[ADR-002](ADR-002-scene-wgpu.md).
