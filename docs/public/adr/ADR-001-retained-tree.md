# ADR-001: retained tree и независимое ядро

Дата: 2026-10-09. Статус: принято как направление M1; retained tree в M0 ещё нет.

## Контекст

Компонентам с выбором строк, focus, редактированием и доступностью нужна устойчивая
идентичность между событиями. Индекс видимой строки или адрес временного Rust
объекта не подходит для идентичности виджета. При виртуализации элементы
появляются и исчезают независимо от срока жизни данных приложения.

M0 содержит три работающих пакета: `rust-desktop-ui-core`,
`rust-desktop-ui-render-wgpu` и пример `gpu-shell`. Сцена прямоугольников проверяет
границу между моделью и renderer; она не реализует дерево виджетов, Ribbon или
TreeGrid.

## Решение

Ядро развивается как retained runtime с arena и идентификатором `WidgetId`,
состоящим из индекса слота и поколения. Идентификатор стабилен до удаления узла.
Повторное использование слота меняет поколение; обращение по устаревшему ID
возвращает отсутствие узла. Конкретное хранилище и публичный Rust API выбираются
при реализации M1, после тестов удаления и повторного выделения.

Логическое дерево хранит структуру и семантическую идентичность. Вычисленные
layout, clips и paint-данные отделяются от логической структуры. GPU resources
остаются в renderer. Ключ строки источника данных и `WidgetId` — разные сущности:
виртуализация не создаёт по узлу на каждую из 100 000 строк.

Состоянием владеет поток event loop. Фоновые задачи передают результаты
сообщениями. Изменения во время обхода дерева откладываются до безопасной фазы.
Планируемый цикл M1: нормализация события → hit test → capture/target/bubble →
изменение состояния → dirty flags → layout/scene → запрос перерисовки.
Measure, layout, paint и semantics получают раздельную invalidation.

`ui-core` и будущие controls не зависят от `winit` или `wgpu`. M0 сохраняет
`Rect`, `Color`, `SolidRect` и `Scene` в `ui-core`; отдельный `ui-graphics`
понадобится при появлении самостоятельной графической подсистемы. Новые crates
выделяются по реальным границам ответственности. Демонстрационная логика
принадлежит примеру `gpu-shell`.

## Альтернативы

- Только immediate-mode интерфейс: потребует отдельной устойчивой модели focus,
  selection и accessibility, поэтому не выбран основой runtime.
- Сырые индексы без поколения: старый ID может незаметно обратиться к другому
  узлу после переиспользования слота.
- Граф взаимных `&mut` или shared pointers: усложняет владение, удаление и
  контролируемые обновления без необходимости для начального runtime.
- Полный набор будущих crates сразу: фиксирует границы до появления реализации.

## Проверка решения в M1

Тесты должны покрывать создание, удаление и переиспользование узлов; отказ по
устаревшему ID; parent/child invariants; порядок маршрутизации событий; focus
после удаления; распространение dirty flags. Эти тесты и сам runtime не входят
в реализованные возможности M0. Расширение сцены описано в
[ADR-002](ADR-002-scene-wgpu.md).
