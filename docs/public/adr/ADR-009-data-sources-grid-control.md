# ADR-009: источники данных и GridControl

Статус: принято. Дата: 2026-10-15.

## Задача

Формам нужны общие источники табличных данных, адаптеры Rust-коллекций и SQLite,
а также GridControl с compiled XAML. Существующий TreeGrid уже предоставляет
виртуализацию, колонки, выделение, query и семантику. BindingContext предназначен
для ограниченной модели формы и хранит числа как f64; передача через него всех
строк БД теряет целочисленную точность и связывает объём данных с деревом формы.

## Решение

`ui-data` владеет типизированными значениями, схемой, стабильными `i64` ключами,
ограниченными снимками, адаптерами и локальным query. Он не зависит от UI,
renderer, оконной платформы или binding scheduler. `DataSource` хранит последний
принятый снимок, revision и диагностическую ошибку. Неудачная операция сохраняет
прежнее состояние. Nullable и тип поля независимы; `i64` никогда не проходит
через `f64`.

`CollectionAdapter` принимает Rust-таблицу и предоставляет application-owned
handle для явной замены. `SqliteAdapter` включается feature-флагом и использует
закреплённый `rusqlite` с bundled SQLite. Это низкоуровневая C-библиотека данных,
без UI или графического движка. Открытие существующего файла, схема и момент
refresh определяются приложением. Изменение ячейки выполняется транзакционно
с проверкой исходного значения и нового snapshot до commit.

`ui-controls` зависит от `ui-data` и `ui-treegrid`. GridControl соединяет
существующий виртуальный TreeGrid с источником, общим TextBox для draft и
retained hosts. Плоское представление не резервирует место для tree expanders;
старый TreeGrid сохраняет свою иерархическую семантику. Данные читаются из
снимка, а SQL и переиндексация выполняются только явными операциями.

`ui-xaml` остаётся компилятором определений. GridControl ссылается на имя
источника из реестра приложения; разметка не создаёт соединение и не исполняет
SQL. Колонки связываются с полями по устойчивым именам. Выбранный ключ передаётся
в BindingContext как точная десятичная строка либо null.

## Последствия

Один источник можно подключать к нескольким представлениям. Состояние editor
и query нужно согласовывать явно: внешний refresh не должен молча заменять
неподтверждённый draft. Шаблоны, бизнес-валидаторы и источник данных сохраняют
раздельную ответственность.

Первый профиль синхронный и ограниченный по объёму. Оба адаптера используют
одинаковую локальную сортировку и фильтрацию. UI-виртуализация не означает
server paging; фоновые запросы, ORM, удалённые источники и SQL server mode
потребуют отдельного развития контракта. Подробности — [data.md](../data.md).
