# Breadcrumb

`Controls::breadcrumb` создаёт строку навигации по иерархическому расположению.
`BreadcrumbPath` содержит непрозрачный текст для редактирования и сегменты
`BreadcrumbSegment { key, label, has_children }`. Ключи уникальны внутри пути.
Контрол не разбирает файловые пути и не выполняет маршрутизацию: приложение
разрешает запрос и возвращает новое принятое расположение.

## Запросы и принятый путь

`breadcrumb_path` возвращает принятое значение; `breadcrumb_draft` — вводимый
текст. F2/Ctrl+L включает ввод, Enter создаёт navigation request, Escape сначала
отменяет IME preedit, затем popup или черновик. Уход фокуса сохраняет черновик,
отменяя незавершённые запросы; автоматического перехода по blur нет.
Left/Right, Home/End перемещают фокус между видимыми сегментами. Alt+Down
запрашивает дочерние элементы ближайшего уровня с `has_children`.

Приложение получает запросы через `drain_breadcrumb_navigation_requests` и
`drain_breadcrumb_children_requests`. Работа провайдера выполняется вне вызова
контрола; ответ передаётся через `complete_breadcrumb_navigation/children`.
Токен содержит владельца, источник, поколение запроса и версию принятого пути.
Токены разных контролов не взаимозаменяемы. Новый ввод, новое намерение,
закрытие popup, blur, смена источника, read-only и удаление отменяют старый токен.
Поздний ответ возвращает `BreadcrumbCompletion::Stale` и не меняет путь.

Ошибочный ответ навигации сохраняет принятый путь и черновик. Неверные метаданные,
дубликаты, циклический child key, слишком большой ответ и ошибка окончательной
сформированной строки отклоняются до изменения представления. Полный ответ
можно повторить с тем же актуальным токеном. `BreadcrumbValidator` проверяет
принятый путь до публикации. Недоступный дочерний элемент не создаёт переход.

`set_breadcrumb_path` загружает принятое значение приложения, отменяя старые
запросы; в историю оно не добавляется. При грязном черновике метод возвращает
ошибку: приложение должно явно вызвать `cancel_breadcrumb` перед заменой.
Та же политика действует при изменении `BreadcrumbSettings.source`.
`BreadcrumbSourceVersion` задаётся приложением; скрытого provider I/O нет.

## Длинные пути и история

При недостатке ширины сохраняются ближайшие уровни, а общий popup показывает
все сегменты с полными подписями. Видимые подписи сокращаются многоточием,
accessible name остаётся полным. Существующие ключи сохраняют WidgetId даже
после overflow или обновления подписи. Фокус скрытого сегмента переходит на
overflow и восстанавливается при расширении, если пользователь оставил его там.

История содержит только успешные переходы, дедуплицируется по последовательности
ключей и ограничена `history_limit` (по умолчанию 20). Выбор истории создаёт
новый запрос; он не обходит актуальную проверку приложения.

## XAML и bindings

```xml
<Breadcrumb x:Name="Location" Value="{Binding Location}"
            IsReadOnly="{Binding ReadOnly}" HistoryLimit="20"/>
```

Literal-профиль использует `Path` и дочерние `BreadcrumbSegment` с `Key`, `Label`,
`HasChildren`. `Value` — типизированный объект, а не строковый путь:
`{ text: String, segments: [{ key: String, label: String, has_children: Bool }] }`.
`breadcrumb_path_to_value/from_value` задают точное преобразование. TwoWay
публикует только принятый путь; source update не заменяет грязный черновик.
Строковый `FallbackValue` для Value не поддерживается.
Ошибочное начальное значение `Value` в compiled форме отклоняет монтаж формы;
последующие ошибки модели сохраняются в diagnostics без замены принятого пути.

## Пределы

До 64 контролов, 64 сегментов, 256 дочерних элементов и 100 записей истории.
Путь ограничен 1024 графемами/4096 байтами UTF-8, ключ — 128 байтами,
подпись — 128 графемами/512 байтами, метаданные пути — 16 КиБ, child response —
64 КиБ. Очередь событий в одном контроле содержит до 128 событий; переполнение
отклоняет следующее завершение до публикации. Встроенные editor/list parts
принадлежат контролу; их независимое удаление или изменение рецепта отклоняется.

История хранится в памяти, файловое сохранение и сетевой провайдер не встроены.
Unit-проверки IME preedit и семантических узлов не заменяют проверку системной
IME или экранным диктором.
