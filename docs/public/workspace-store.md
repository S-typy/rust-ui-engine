# Конфигурация рабочей области

`workspace::WorkspaceStore` сохраняет явно зарегистрированные настройки нескольких
компонентов в одном версионном JSON. Он не обходит дерево элементов и не включает
автоматически текст документов, значения редакторов, секреты или `WidgetId`.
Чтение и запись файлов принадлежат приложению; автоматического save/restore нет.

## Реестр и форматы

Каждая запись имеет стабильный идентификатор, идентификатор типа, версию и
ограниченную строку payload. Строка сохраняет исходный формат компонента:
его codec самостоятельно проверяет неизвестные и повторяющиеся поля.
Внешний envelope проверяет их строго и отвергает неподдерживаемую версию,
чужой workspace ID, отсутствующие, лишние и повторяющиеся компоненты.

`WorkspaceCodec<T>` определяет `kind`, `version`, `validate`, `encode` и `decode`.
`decode` получает предыдущую принятую конфигурацию только для чтения, например
для проверки идентификаторов панелей в существующем каталоге. Старую версию
codec либо явно мигрирует, либо отклоняет. Более новая версия отклоняется самим
хранилищем. После миграции новая конфигурация снова проверяется и кодируется.

`register` и `replace` проверяют значение и размер окончательного envelope до
замены принятого состояния. `get::<T>` возвращает типизированную ссылку только
для чтения; неподходящий Rust-тип возвращает `None`. `save_json` использует
проверенные payload и не вызывает codec повторно. Порядок записей стабилен.

`DockWorkspaceCodec` использует существующий `DockLayout` и его JSON codec.
Сохраняются размещение панелей и поддерживаемая версия snapshot. Названия
документов, содержимое панелей и бизнес-данные в payload отсутствуют. Каталог
панелей берётся из принятой конфигурации; неизвестная панель отклоняет restore.

## Атомарное восстановление

`prepare_restore` декодирует все записи в отдельные значения, проверяет их
форматы, миграции и общий размер. Ошибка любой записи оставляет все принятые
значения и generation прежними. Возвращённый `PreparedWorkspace` эксклюзивно
заимствует store: пока он существует, другая операция не может изменить store.
Удаление guard отменяет подготовку. `commit` публикует все подготовленные
значения одновременно и не возвращает ошибку; переполнение generation
проверяется до создания guard.

```rust,ignore
let pending = store.prepare_restore(&saved_json)?;
let layout = pending.get::<PanelLayout>("layout").ok_or("wrong type")?;
let mutations = prepare_retained_layout(&ui, layout)?;
ui.runtime.apply_batch(&mutations)?;
pending.commit();
```

Хранилище гарантирует атомарность собственных типизированных состояний.
Произвольный набор вызовов к живым `Controls` сам по себе не становится
транзакцией. Для отображения приложение сначала проверяет required handles и
готовит все изменения, затем применяет одну атомарную `Runtime::apply_batch`
и вызывает `commit`. После успешного batch до commit нельзя выполнять другие
операции, которые могут завершиться ошибкой. `restore_json` — сокращение для
восстановления только store без проекции на живые элементы.

Codecs обязаны быть чистыми: без I/O, изменения внешних объектов и живых
элементов. Конфигурация должна владеть своими данными; алиасы на внешние
`Rc<RefCell<_>>` не соответствуют этому контракту. Исключения в callbacks или
`Drop`, аварийное завершение процесса и внешние побочные эффекты не относятся
к гарантиям обычного `Result`.

## Ограничения и пример

- До 64 зарегистрированных компонентов и 1 MiB UTF-8 окончательного JSON.
- Идентификаторы: 1–128 ASCII букв, цифр и символов `_ . - /`.
- Версии компонентов положительные; версия envelope независима от них.
- Диагностика содержит ID компонента и до 512 UTF-8 байт причины. Payload не
  добавляется в сообщение автоматически; codec не должен включать в ошибку
  конфиденциальные данные.
- Полный набор зарегистрированных компонентов обязателен; частичного merge и
  молчаливого пропуска неизвестных записей нет.

`cargo run -p rust-desktop-ui-controls --example workspace_restore` выполняет
самостоятельный пример без окна: два codecs сохраняют размеры и видимость,
формат размера мигрирует с v1 на v2. Ошибка второго участника оставляет UI и
store прежними. Успешное восстановление меняет расположение через один batch,
сохраняя WidgetId, draft и принятое значение редактора. Пример не читает файлы
и не является проверкой GPU или нативного ввода.
