# Защищённый ввод

`PasswordBox` — однострочное поле с отдельным хранилищем значения. Оно не
использует обычный `TextBox` session, `TextChanged`, `EditEvent` или `Text` binding.
Значение доступно приложению только через явные методы:

- `password_value(id)` возвращает заимствованный `PasswordRef`;
- `set_password_value(id, text)` проверяет и загружает значение атомарно;
- `take_password_value(id)` возвращает `PasswordValue` и очищает поле.

`PasswordRef` и `PasswordValue` раскрывают строку только через `expose_secret()`.
Их `Debug` скрывает содержимое; `PasswordValue` не реализует `Clone`. Приложение
отвечает за копии, которые оно создаёт после явного раскрытия. Это не зашифрованное
или закреплённое хранилище памяти; обнуление освобождённых аллокаций не обещается.

```xml
<PasswordBox xmlns="urn:rust-ui-engine:ui"
             xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
             x:Name="AccountPassword"
             AutomationName="Пароль учётной записи"
             PlaceholderText="Введите пароль"
             MaxLength="256" AllowPaste="True" AllowReveal="True"
             RevealDurationMs="3000" />
```

XAML создаёт пустое поле. Литералы и bindings `Text`, `Value`, `Password`
отклоняются при компиляции; обычные бизнес-валидаторы редакторов здесь не
применяются. Разрешены настройки оформления, размеров, доступности и видимости.
Обработчик отправки получает значение явным вызовом Rust API.

## Ввод и события

По умолчанию разрешены 256 графем; верхние границы — 4096 графем и 16384 байта.
Переводы строк, управляющие символы и Unicode-разделители строк отклоняются
целиком. Слишком длинная вставка не обрезает пароль молча. Настройки и
программная загрузка, не проходящие проверку, сохраняют прежнее значение.

Клавиатура поддерживает выделение, перемещение по графемам и словам, Home/End,
удаление и вставку. `AllowPaste=False` блокирует Ctrl+V, Shift+Insert и отдельный
путь `paste_input`. Copy/Cut, Ctrl+Insert и Shift+Delete не передают пароль в
буфер обмена. Undo/Redo не сохраняют историю пароля. `IsReadOnly` запрещает
пользовательское изменение, сохраняя явную программную загрузку.

`drain_password_events()` выдаёт только идентификатор поля и вид события:
`Changed`, `Submitted`, `Revealed`, `Hidden`. Enter без повторения и модификаторов
создаёт `Submitted`; событие не содержит текст или выбранный фрагмент. Escape
отменяет композицию и скрывает временный показ, но не восстанавливает прежний
пароль. Подтверждение бизнес-операции выполняет приложение.

## Временный показ и доступность

Кнопка показа находится справа и возвращает фокус полю. Показ возможен только
для непустого активного поля без композиции; по умолчанию он длится три секунды.
`RevealDurationMs` задаётся в миллисекундах, разрешён интервал 1–10000.
Уход фокуса, отключение, скрытие, отсоединение и изменение ввода прекращают показ.
Обычное изображение содержит одну точку на графему; длина значения видна.
Если значение выходит за пределы подготовки текста, временный показ отклоняется
до изменения состояния. Само значение сохраняется и остаётся доступным через
явный API; маскированное поле продолжает работать.

Accessibility представляет поле как защищённый ввод без текстового значения.
Имена поля и кнопки остаются доступными. Пример формы исключает символы,
clipboard/IME payload и значение поля из своей диагностики. Собственный host
должен проверять `password_input_focused()` перед журналированием входящих
событий; Controls не может очистить журнал, который host уже записал.

Открытый текст временного показа помечается `TextRun::sensitive`; его `Debug`
редактируется, а текстовый движок не сохраняет такой layout в общем кэше. При
завершении показа предыдущие команды сцены и layout поля очищаются. Реальный
рендеринг показа всё равно требует доступного приложению текста и глифов.

На Windows host отключает native IME composition для защищённого поля и
отклоняет запоздалые события предыдущего IME session. Unicode можно вводить
непосредственно или вставлять, если это разрешено. Остальные платформы получают
`ImePurpose::Password`; их нативное поведение требует отдельной проверки.
Один input-scope hint не заменяет отключение текстовых служб Windows.
[Контракт Microsoft InputScope](https://learn.microsoft.com/en-us/windows/win32/api/inputscope/ne-inputscope-inputscope).
