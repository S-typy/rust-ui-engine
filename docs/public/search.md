# SearchBox и подсказки

`Controls::search_box` создаёт поле `Query`, кнопки очистки и поиска и сохраняемый
список подсказок. `SearchBox` возвращает идентификаторы контейнера, редактора,
кнопок, `Flyout`, `ListBox` и строки состояния. Эти части принадлежат одному
контролу: удаляется весь контейнер, отдельное удаление обязательных частей
отклоняется.

`Query` — текущий текст поиска. Он не требует подтверждения при уходе фокуса.
`set_search_query` обновляет его с обычной историей редактора; `search_query`
читает актуальный текст. Очистка не запускает поиск. Escape отменяет текущую
IME-композицию; следующее нажатие закрывает подсказки, сохраняя текст.

## Запросы к поставщику

После изменения текста активного поля контрол создаёт `SearchSuggestionRequest`.
Приложение получает запросы через `drain_search_suggestion_requests` и выполняет
собственный поставщик. В очереди хранится только последний запрос каждого поля.
Токен можно передать рабочему потоку; `complete_search_suggestions` вызывается
на потоке интерфейса с `Ok(Vec<SearchSuggestion>)` или `Err(String)`.

Токен содержит доступные для чтения `owner`, `query`, `generation` и
`is_cancelled`. Его идентичность создаёт контрол. Новый текст, закрытие,
отключение, скрытие, уход фокуса и удаление отменяют предыдущий запрос.
Поставщик может добровольно прекратить работу при отмене. Поздний, повторный
или чужой ответ возвращает `SearchCompletion::Stale` и не меняет интерфейс.
Исполнение задач, сетевой транспорт и планировщик задержек остаются у приложения.

Корректный ответ возвращает `Applied`. Некорректные ключи, превышение лимитов и
ошибки поставщика дают `Rejected` и отдельное событие `SuggestionsFailed`.
Некорректный ответ сохраняет прежний источник списка и введённый текст; прежние
строки скрываются на время сообщения об ошибке и недоступны для выбора.
Недопустимое сообщение об ошибке заменяется ограниченным сообщением контрола.

`SearchSuggestion` содержит стабильный `key`, отображаемый `text`, значение
`query`, необязательный `description` и `enabled`. Ответ не меняет `Query`.
Список сохраняет фокус в редакторе; стрелки перемещают выделение и пропускают
отключённые строки. Enter выбирает выделенную подсказку. Без выделенной строки
Enter запускает поиск; Ctrl+Enter явно запускает поиск текущего текста.

## События и история

`drain_search_events` возвращает отдельные события:

- `SuggestionChosen { key, query }` — подсказка выбрана и заполнила поле;
- `SearchRequested { query }` — приложение должно выполнить поиск;
- `SuggestionsFailed { message }` — поставщик либо проверка ответа завершились ошибкой.

Политика `SearchChoicePolicy::FillQuery` используется по умолчанию: выбор не
запускает поиск. `FillAndSearch` создаёт последовательно `SuggestionChosen` и
`SearchRequested`. Повтор клавиши Enter не дублирует эти действия.

`submit_search` создаёт событие поиска, `choose_search_suggestion` выбирает
доступный ключ, `close_search_suggestions` закрывает список и отменяет запрос.
`request_search_suggestions` явно повторяет запрос активного поля.

История пополняется только при `SearchRequested`: непустой текст перемещается
в начало, точные дубликаты удаляются. `search_history`, `set_search_history` и
`open_search_history` позволяют читать, заменить, очистить и показать историю.
Alt+стрелка либо стрелка в пустом поле показывает историю. Её выбор подчиняется
той же политике, что и подсказки. Автоматического сохранения на диск нет.

## Настройки и границы

| Настройка | По умолчанию | Допустимо |
| --- | --- | --- |
| `min_query_length` | 1 | 0…`max_query_length`, в графемах |
| `max_query_length` | 256 | 1…4096 графем; дополнительно 65 536 байт UTF-8 |
| `max_suggestions` | 100 | 1…1000 |
| `history_limit` | 20 | 0…100 |
| `popup_size` | 360×280 | ширина 160…4096, высота 80…4096 логических пикселей |
| `choice_policy` | `FillQuery` | `FillQuery`, `FillAndSearch` |

В одном `Controls` допускается до 64 полей. Ключ подсказки непустой и занимает
не более 128 байт; подпись и описание — по 4096 байт. Суммарный ответ ограничен
одним MiB. Текст проходит общую проверку графем и бюджета формирования текста;
см. [редактирование текста](text-editing.md). `Query` однострочный, без NUL.
Ограничение внутреннего редактора можно уменьшить, но нельзя отключить либо
увеличить сверх настроек SearchBox; подтверждение при уходе фокуса для него
не включается. Read-only сохраняет чтение и выделение текста и блокирует
пользовательские поиск, очистку и выбор подсказки.

Очередь событий ограничена 256 событиями на поле. Приложение регулярно
вызывает `drain_search_events`; переполнение отклоняет действие до изменения
текста и истории. Источник подсказок и история доступны через явные API;
контрол не выполняет неявных запросов к базе данных.

## Связь с данными

`SearchTarget { fields, operator, comparison }::query_request(query)` строит
`QueryRequest` для общего [движка запросов](query.md). Непустой текст создаёт
`Criteria::Any` из `TextMatch` по выбранным полям. Пустой текст снимает фильтр.
Допускается 1…32 уникальных имени поля по 256 байт. Проверка существования и
типов полей, null и сравнение текста принадлежат `QueryEngine`.

Тот же `QueryRequest` можно передать поддерживающему запросы источнику данных.
Приложение применяет результат к своему GridControl или другому потребителю;
SearchBox не владеет таблицей и не меняет её без обработчика приложения.

## Compiled XAML

```xml
<SearchBox x:Name="DocumentSearch"
           Query="{Binding Query}"
           PlaceholderText="Найти документ"
           MinQueryLength="2" MaxLength="256"
           MaxSuggestions="50" HistoryLimit="20"
           PopupWidth="420" PopupHeight="280"
           ChoicePolicy="FillQuery" />
```

`Query` по умолчанию использует `TwoWay` и `PropertyChanged`. Привязка читает
текущий ввод: выбор подсказки и очистка также обновляют модель. Для Query
допускается только `UpdateSourceTrigger=PropertyChanged`; подтверждение значения
редактора не участвует в поиске. `IsReadOnly` и `PlaceholderText` поддерживают
обычные привязки. Общие размеры, видимость, доступное имя и оформление редактора
задаются свойствами формы.

`Text`, `Value`, `CommitOnLostFocus`, `IsRequired` и `ValidationMessage` для
SearchBox отклоняются компилятором. `MaxLength` обязателен на уровне определения
и по умолчанию равен 256; значение 0 не отключает ограничение. Остальные пределы
и значения по умолчанию совпадают с таблицей настроек выше. Вложенное содержимое
SearchBox не допускается.

При навигации по подсказкам текстовый фокус остаётся в редакторе. Выделенная
подсказка становится активным элементом для accessibility: экранный диктор
получает её текст, положение и состояние выбора. Закрытие списка, очистка
запроса и потеря фокуса убирают эту связь.

Поставщик подсказок, обработка `SearchRequested` и сохранение истории подключаются
в Rust через возвращённые идентификаторы и API контрола. XAML не создаёт сетевых
запросов или обработчиков приложения.
